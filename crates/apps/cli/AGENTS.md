# `axioval-cli`

Strict command-line entry point for normalized Axioval packages and validation runs.

CLI output and exit codes are public automation contracts. Parse packages fail closed, write diagnostics to stderr, and use non-zero status for invalid input or execution failure.

- `--ruleset` repeats for `check` and `validate`, compiled through `compile_rulesets`; qualified rule ids (`package-id/rule-id`) are a report contract.
- `check` exit status: 0 complete and clean, 3 findings, 4 not evaluated without findings, 1 failure, 2 usage (clap). Status 4 exists so an incomplete check can never exit 0; never fold it into 0.
- Build every output before writing any, so a failing run leaves no partial report or archive.
- The CLI is the host: it may enable several facade features and compose an adapter with a sink. Libraries never do.
- Never read the clock for BCF output when `--bcf-date` or `SOURCE_DATE_EPOCH` is given.
- `src/digest.rs` owns the saved result format (`CheckOutput`) and its two views. The summary must stay bounded by distinct groups, never by entry count; the listing must page. Every "next" hint must run unchanged in a POSIX shell: quote through `shell_quote`, which quotes `#` because an unquoted `#` starts a comment.
- Report tables are the `tables` section: one summary group per table (rows counted, columns as the message, a grouped table's group columns first), one listing entry per row (a grouped row prefixed by its group values in brackets). They never affect the status. `report --csv` (`digest::table_csv`) prints exactly one table, selected by `--rule` and `--table`; its header (`scope`, group columns, `<id>_lower`/`<id>_upper` per numeric column) is a public contract, and an unknown value is empty, never zero.
- The result's `objects` field is additive (`serde(default)`), so results saved before it existed still load. It labels resource objects from `Report::resources` (`Report::object`), never from the project alone.
- `src/geometry.rs` is the IFC→Axiolid bridge. It belongs here and nowhere else: the adapters must not depend on each other. Every object must end in exactly one state: exact mesh, tessellated mesh, no body, or unmeasured. Never declare a physical product bodiless because meshing failed; that makes it vanish from contact and free-space checks. A physical product with no `Body` of its own is measured through its parts (`Composer`): the session's `IfcRelAggregates` edges (`RelationshipSelectionServiceHandle::edges`, one listing, never a query per object), inner wholes first, then `AxiolidGeometry::compose` after `with_boundaries`. Any unmeasured part leaves the whole unmeasured naming it (`no body representation of its own, and …`); no parts stays unmeasured as `no shape representation` when `Representation` is `$` (model data: also one `shape.no-representation` integrity warning per object, `GeometryReport::model_data`, never measured as empty) or as `no body representation; it has <identifiers>` when it has representations none of which is a body; an unreadable edge listing leaves every such whole unmeasured with the reason. `geometry.composed` is additive. A product left unmeasured by its own meshing (a compiler refusal), or a whole left unmeasured, gets a bound for the space service: a whole whose parts could not be composed the box of its parts (`AxiolidGeometry::parts_bound`: measured parts' boxes and unmeasured parts' bounds, none if any part is unbounded), otherwise the box its `Box` representation states (`stated_box`: every `IfcBoundingBox` corner placed by the context's world coordinate system above the placement chain, never the corner and extents as world axes). Anything unreadable gives no box, never a guessed one; an unaligned source's products get none, and a whole measured through its parts is measured, never bounded. `tests/check.rs` pins a layered wall, a stair, a roof with a bodiless slab and the whole/part pairs a clash must not report. A whole's own openings (#223, `WholeOpenings`): bodies are registered only after them. Each opening of a whole is compared with each measured part beneath it (at any depth) by `cuts`: two exact bodies cell by cell of the opening's mesh (`OpeningCell`: a convex connected piece, one prism per cap triangle of an extrusion, else the cells its own face planes split its box into (`arrangement`, #316: each in or out by the winding number of its centre, signed by the piece's orientation; none when it crosses itself or exceeds `MAX_CELL_PLANES`/`MAX_CELLS`), else a convex cell holding the piece, which only ever decides clear and is also tried when an arrangement cell stays open), the part cutting a cell when its surface reaches into the cell's core shrunk by `TOUCHING_DEPTH` (10 µm) or the core lies inside it by winding number (`cell_cut`); what that leaves open and every tessellated pair by the certified shared volume (`shared_volume_cut`: beyond a layer `TOUCHING_DEPTH` thick over the opening's faces inside the part's box (`contact_area`) or the opening inside the part cuts, within `TOUCHING_VOLUME` or apart is clear, between is undecided; never widen clear to the layer, which a volume cannot show reaches nowhere deeper). Never decide it by a penetration witness, which reads deep on a face an opening shares with a hole already cut, and never by the kernel's shared volume alone: on cut Brep layers it is refused or spans `[0, the part's volume]` (corpus m01). It is subtracted only from the parts it cuts (`mesh_less`: the part's net body less the opening's `Body`, in world coordinates; a several-solid operand is refused by the graph, never cut in part), and a part it cannot be decided for, lies around, or cannot be cut from (nothing left of it is a named refusal too, never #310's voided body, which is about its own openings) is unmeasured naming the opening and the whole, which then fails closed naming the part. An opening without a body to compare leaves the whole unmeasured naming it (`refused`); a `Reference`-only one under `TakeAsApplied` is taken as applied to the whole (`reference_only` mirrors ifc-geometry's reading; never widen it). Every cut body and each whole holding it is named with `with_whole_openings` (`;whole-openings:`), and `geometry.whole_openings` (additive) lists each decided opening with the parts it was subtracted from. `tests/check.rs` pins an uncut layered wall with a pipe through its door, the same wall already cut (`Body` and `Reference` openings) unchanged, a turned wall with a rebated Brep window flush with its cut layers unchanged (#316), and the refusals; the unit tests `a_wholes_opening_cuts_a_part_only_where_it_reaches_into_its_material`, `a_wholes_opening_of_several_pieces_or_any_profile_is_read_by_its_shape`, `a_wholes_stepped_opening_is_read_cell_by_cell_of_its_planes` and `a_wholes_opening_cuts_by_volume_only_beyond_the_cut_tests_depth` pin the decision. The planarity check may only grow by structures proven planar; anything unrecognised stays tessellated. A section profile is polygonal only with every fillet and edge radius absent or zero (its straight and sloped edges are exact); any radius is chorded.
- Space-boundary coverage registers every `IfcSpace` and every `IfcRelSpaceBoundary` naming one. A boundary's `ConnectionGeometry` is read through `ifc-spatial`'s `SpaceBoundary::connection_geometry` and lowered through `ifc-geometry`'s `lower_connection_surface` (surfaces, face surfaces, face-based surface models) in the frame `product_representation_frame` gives the space's `Body` representation (openbimrs/ifc#164), the same frame lowering places the body in; never rebuild that frame or place the mesh afterwards. A curve-bounded plane takes the frame on its basis plane only (openbimrs/ifc#163). A space without a body representation falls back to its placement; its coverage is refused anyway. Anything not lowered (no geometry, not a surface, refused by the lowering or compiler) is an unmeasured boundary, never skipped. `axiolid-mesh-compile` is a direct dependency only to require 0.3.5 (curve-bounded planes, axiolid/kernel#192; section profiles meshed from their exact contour, axiolid/kernel#193; voids tangent to a host face, axiolid/kernel#194).
- Every compiler refusal goes through `compilation_refused` and leaves the object unmeasured. `BudgetExceeded` (since mesh-compile 0.3.8 and construct 0.3.10 a turn needing more than 4096 steps to meet the chord tolerance, axiolid/kernel#231) gets a reason naming the tolerance and the resource; never retry it with a coarser tolerance or accept a coarser mesh under the declared deviation. `tests/check.rs` pins it with a ring 5 km round. Every mesh goes through `compile`: a planar one (a bounded half-space with a polyline boundary included) is exact and compiled with plain `compile_mesh`, since a deviation report would only pay to measure its booleans; a curved one goes through `compile_mesh_with_deviation` (mesh-compile 0.3.10, axiolid/kernel#232, #235) and is declared with the report's certified bound as returned (never the 1 mm budget by assumption; a curved boolean's is measured against the exact compiler's result and reads close to the budget), and one with no bound (`Unbounded`: booleans the exact compiler refuses, tapered extrusions, sectioned spines) is refused through `uncertified` and left unmeasured, for bodies, opening voids and space-boundary surfaces alike. A disk swept round an unfilleted polyline corner is mitred and proven within the budget again (mesh-compile 0.3.12, construct 0.3.13, axiolid/kernel#245), so it is measured; a closed polyline and a fillet radius equal to the disk radius are still refused by the compiler by name (#248) and left unmeasured; `tests/check.rs` pins those, and both a roof-clipped wall with a round window and a beam with a hole tangent to its flange (both certified; the latter since mesh-compile 0.3.13, axiolid/kernel#243). Warped authored faces (axiolid/kernel#254, #257, #261): since mesh-compile 0.3.14 the compiler reports every `PolygonMesh` face and every B-rep face without a surface warped beyond the tolerance as `Certified` with the width of the slab its corners span about its fit plane (details `"non-planar authored face"`, `"non-planar face without a surface"`, `WARPED_FACES`), scaled by placements; it holds every reading of the face (a lifted-corner quad's two triangulations, a saddle's `2 h`). `compile` declares the body within that reported bound (`warped_width`): a planar graph with such faces outside booleans (`authored_leaves`) is compiled with a report for it, a curved one's report includes it. Never compute a warp here. Each such face under a boolean is compiled alone with a report, and a warped one leaves the body unmeasured: the compiler bounds no boolean of a polygon mesh or B-rep (the exact compiler refuses both). A graph beyond `NODE_BUDGET` is refused. Unit tests pin the lifted corner and the saddle against the gap between their triangulations, placement scaling and the boolean refusal; `tests/check.rs` a faceted wall with a corner lifted 5 cm. Faces are triangulated by the certified clipper (#260): rings bounding no region are refused by name (unmeasured); a face ring that crosses or runs back along itself is model data (`self_intersecting_face`, one `shape.self-intersecting-face` integrity warning per object, #298), while one that overlaps itself (a keyhole, axiolid/kernel#270) or finds no ear (axiolid/kernel#269) is not; a measured product whose mesh is no closed two-manifold and whose `Body` items' faces, as authored, leave edges bounding one face only (`geometry/authored_faces.rs`: face sets, faceted B-reps, shell- and face-based surface models through mapped items, corners by exact coordinates, item by item) is model data too (one `shape.open-surface` integrity warning per object with the count, #311); a face set repeating its corners per face is not, since the adapter shares equal corners (#308); rings touching inside a neighbouring face's edge leave a T-junction that `audit_mesh` reads as open, so the body is never a closed solid to any service (unit test `a_t_junction_…`). A disk swept along an `IfcGradientCurve` is certified (#252); `tests/check.rs` measures one.
- A host whose net body compiles to no triangles while its gross body (`NetLowering::gross`, re-lowered in a fresh session, `gross_has_triangles`) compiles to some is unmeasured as `voided_body_reason` (its openings remove its whole body), model data with one `shape.voided-body` integrity warning per object (`VOIDED_BODY`, #310); never measure it as empty, and keep `NO_TRIANGLES` for a body empty before any opening.
- Hosts are meshed through `lower_product_net_with` with the source's `Parsed::net` (`net_options`): `ReferenceOnlyOpenings::TakeAsApplied` only for a snapshot schema of `IFC4` or `IFC4X3`, whose `IfcOpeningElement` definition states that a `Reference` representation is not subtracted (engine#218, openbimrs/ifc#351); every other release refuses. Never decide it here from geometry or names: `ifc-geometry` takes an opening as applied only when every representation is `Reference`, and an opening with none or with another stays refused. Each taken opening is named on the host (`AxiolidGeometry::with_applied_openings`, so evidence carries `;applied-openings:`) and in the result's additive `geometry.openings_taken_as_applied` with its reason (`applied_reason`; an `AppliedReason` this bridge does not know leaves the host unmeasured). Its void is its `Reference` solid (`reference_void`), only for openings some host took as applied. `tests/check.rs` pins a host measured with a `Reference` opening, one voided by a `Body` opening and one left unmeasured by an opening without representation. Since `ifc-geometry` 0.13 (openbimrs/ifc#388) the openings are subtracted in the host's frame and the net root (like `gross`, each `Subtraction::body` and `result`) is an `Instance` with the host's world transform above them; `compile`, `planar`, `authored_leaves` and `exact_boundary` walk through it, so never match the root as a boolean or read a `Subtraction::body` as the placed solid. `tests/check.rs` pins a wall with flush openings under a georeferenced, turned site (engine#303).
- IFC4X3 stations, `IfcOffsetCurveByDistances` and sectioned solids and surfaces lower through `ifc-geometry` (≥ 0.9, openbimrs/ifc#307); a sectioned solid stays unmeasured until the mesh compiler certifies a bound between stations, and stations it refuses by name (an `IfcParameterValue`, a tangent discontinuity, a plain `IfcCompositeCurve` basis, openbimrs/ifc#346) stay unmeasured with that reason. A product on an `IfcLinearPlacement` is placed by deriving its frame from the basis curve (engine#224, `ifc-geometry` ≥ 0.10, openbimrs/ifc#353, #355): every lowering goes through `session()` (`LoweringSession::with_curve_evaluator(&EVALUATOR)`, the `axiolid-evaluate` reference evaluator) and every placement read through `world_transform` or `product_representation_frame_with_evaluator`; never call `LoweringSession::new`, `product_world_transform` or `product_representation_frame` for a product here (only `Linear`'s own check reads alignments' local placements plainly). A cached `CartesianPosition` is verified (`CACHED_POSITIONS` = `CachedPositionPolicy::Verify`, #354); never switch to `Trust`, which would place a product by a stale cache. `Linear` (per source, `Parsed::linear`) refuses every linear placement whose derivation would ignore a stated frame (openbimrs/ifc#357: a `PlacementRelTo` off the identity, a basis curve held by a product placed off the identity, or held by no representation while an alignment is), and `mesh`, `reference_void`, `stated_box`, `space_frame` and the levels check it first (a host also for its openings), so such a product is unmeasured with the reason, never misplaced and never bounded; drop it only once `ifc-geometry` composes both. `tests/check.rs` pins an `IfcParameterValue` refused by name (#347), a length placed, a disagreeing cache refused and an agreeing one placed, and the #357 refusals; the unit test `a_lateral_offset_places_a_product_left_of_its_curve_and_upright` pins #355.
- `src/geometry/alignment.rs` is the `AlignmentService` (engine#252), registered with `--geometry`. Each `IfcAlignment` is read as an elevated centreline: its `Axis` curve lowered through `session()`, else `ifc_alignment::gradient_curve3`; a banked curve by its base; its placement and context must be the identity (`rigid` refuses any other, naming openbimrs/ifc#357; allow rigid frames only once `ifc-geometry` composes alignment placements). Reference points are placement origins through `world_transform`, and a placement `Linear` refuses is refused with that reason. The foot is certified, never searched for by sampling alone: bisection of `g(d) = (P - c) . c'` pruned only by the Lipschitz bound from `curve_derivative_bounds3`, split at `continuity_breaks3`; values widened over the winning bracket by the same bounds, with `slack` for the evaluator. Overlapping candidates are ambiguous, an end nearest is off the range; never clamp or pick. Parameters follow their laws (`curvature`, `gradient`, `cant`, each refusing a law it cannot bound by name); add a law only with a bound proven over a stretch, never by sampling. Unit tests pin straight, arc, hairpin ambiguity, off-range and the gradient-curve fixture; `tests/check.rs` judges cubes by `station` and `offset` along an alignment.
- `src/geometry/alignment/section.rs` cuts sections and sweeps clearance envelopes (engine#253) over the bridge's `AxiolidGeometry` along the same centrelines, so an alignment refused for positions (off the identity, openbimrs/ifc#357) is refused here too; never compose its frame here. The section frame is the plan frame (horizontal left normal, `+Z` up). Only a closed mesh is cut (each directed edge matched by its reverse; a body measured through its parts is refused for a section), with one vertex classification and one canonical cut point per edge, so segments close exactly; the radius is the certified deviation plus `frame_error`. A sweep step is cleared only by the 3D test of triangles clipped to the slab around its mid section against the envelope grown by `D = h (B1 + |u|max B2 / speed)` plus the deviation and the frame's error, or by the winding number when no triangle is that near; a near body is proven inside by a section witness or the step halved (`DEPTH`, `SWEEP_BUDGET`), and what stays undecided is `Possible`, never `Clear`. Unmeasured or open bodies refuse the sweep. Unit tests pin a box's area and thickness, straight and curved sweeps, thin plates crossing between samples (never clear) and the refusals; `tests/check.rs` judges `envelope_intrusions` and `station_section_area` end to end.
- With `--geometry`, `attach` also builds each body's exact boundary from the lowered graph its mesh is compiled from (`axioval::axiolid::exact_boundary`), never from a second reading of the IFC entities, so placement and mirroring are the mesh's. It registers only boundaries that pass `check_exact_boundary` (with `with_exact_body`: a body less its extruded openings or clipped by half-spaces is exact where the kernel's boolean report is empty and perturbed by what it reports otherwise, several items stay in the body's frame), and only when some tessellated body has one. `--no-exact-boundaries` turns it off; `compare` builds them only with `--geometry-mode mesh` (the surface distance reads them), with the same opt-out. `geometry.exact_boundaries` in the result is additive and left out at zero.
- Register a geometry service only when every role it needs can be read from IFC; otherwise leave it unregistered so its rules report `missing-service`.
- `with_levels` declares every `IfcBuildingStorey` a `spans-level` level: its placement's world height up to the next storey's of the same spatial parent. A tilted or unreadable placement, or a height shared with a sibling, is an unmeasured level, never a guessed band.
- Every model is read through `import` in `main.rs` (`compare` too): an ifcZIP archive (zip magic or `.ifczip`) through the adapter's `read_ifc_zip`, named `archive/member`, and the member's STEP bytes are what geometry meshes. Never unzip here. An ifcXML document (`is_ifc_xml`) is imported with `import_ifc_xml_session`, and the bridge parses its bytes with the adapter's `read_ifc_xml`, never the codec directly, so geometry sees the same proven model; STEP bytes likewise go through the adapter's `read_ifc_step` (the session's reader, which accepts a REAL without its decimal point and reports it), never `StepCodec`. `ifc-step` is a dev-dependency only.
- `--model PATH[:DISCIPLINE]` repeats: each file is imported as its own session and `EvidenceSession::federate` combines them before geometry is attached. The bridge meshes every source into one set only where it shares the first source's frame (`unaligned` in `geometry.rs`, through `axioval_rules::compare_coordinate_systems(..).shares_frame()` with the default tolerances); every physical object of another source is unmeasured with the reason, and a source whose coordinate system cannot be read is never assumed aligned. Never re-align meshes by a map conversion here. It looks each object's model up by its source, builds spatial trees per source, and binds every service to all snapshots. Never key anything on a bare local id: two files share `#10`. Each model's file name is stated as its source's `fileName` metadata. `--discipline-map FIELD:PATTERN=DISCIPLINE` is applied after federation; the result's additive `sources` field lists each source's discipline and origin (`declared`, `mapped` with rule and value) or why the map left it without one.
- `src/compare.rs` is `axioval compare`: two single-model sessions matched by `GlobalId` through `axioval_rules::compare_sessions` (`--property-set` and `--all-property-sets` list sets through enumeration; relationship kinds always, `with_relationships`). The same comparison as a rule is the `model-comparison` capability over `check --model a.ifc:base --model b.ifc:revised`; `tests/check.rs` runs it. Its result is a `CheckOutput` with the additive `comparison` field (owned by `digest.rs`), so `report`, `--summary` and `--bcf` stay shared through `emit`; exit status as for `check`. Two files with one name become `name@base` and `name@revised`; never let the two revisions share a source id. `--geometry-mode mesh` (requires `--geometry`) compares surfaces across the two sessions' own proximity services (`with_mesh_geometry`); its records carry an additive `witness` per change and the comparison's `geometry_mode`, both omitted otherwise so bounds results stay byte-identical; a pair with exact boundaries on both sides is measured between them (measure `boundary`). `tests/compare.rs` runs it end to end, round columns between boundaries included.
- Walkability takes every role from its request; metric routing takes surfaces (`IfcSpace`), portals (`IfcDoor`, opening voids) and connectors (stairs, ramps, transport elements) from IFC classes. Never declare a door clear width from `OverallWidth`: it includes the lining, and an overstated clear width turns an undecided route into a false pass.
- BCF cameras come from `geometry::bounds`: the proximity service's enclosing extent of each object the report names, only with `--geometry`. An unmeasured object is left out, never estimated; without `--geometry` pass `None` so the archive stays byte-identical. `--bcf-version 3.0` fails (status 1, nothing written) when a viewpoint has no camera.
- BCF colouring is on with `--geometry` or when `--bcf-subject-color`/`--bcf-related-color` is given, off with `--bcf-no-color`; without any of them and without `--geometry` pass `colors: None` so the archive stays byte-identical.
- `--bcf-isolate` sets `Options::isolate` and `--bcf-section-box` sets `Options::section_box`; neither is on by default.
- `src/ids.rs` is `check --ids` and `ids translate`: the document is translated by `axioval-ids` in memory, and a specification with any gap runs none of its rules (its folder is dropped) and is listed on stderr and in the result's additive `ids` field. A check with such a specification never exits 0 (4 without findings); `ids translate` exits 4 when it left one out. Both paths run the same packages, so `ids translate` then `check --ruleset` reports as `check --ids` does; `--ids-filter` hands a selector file to `Options::with_filter` and is recorded in the `ids` field; `tests/ids.rs` pins it, the storey prefilter included. `ids export` hands its packages to `axioval_ids::export`, lists every rule not exported on stderr, and exits 4 when it wrote the document without some, 1 (writing nothing) when none is exportable; `tests/ids.rs` pins a clash rule listed beside an exported property rule. The document is audited first (`TranslateError::Invalid`): any audit error exits 1, writes nothing and lists every finding (`digest::IdsAuditFinding`); warnings never refuse or change the status, and go to stderr and the `ids` field's additive `warnings`.
- `--bcf-snapshots` makes `geometry::attach` keep each meshed object's
  triangles (`GeometryReport::meshes`, `keep_meshes`) and exports through
  `bcf::export_with_snapshots` with `bcf_snapshot::Renderer`. Without
  `--geometry` it fails before writing anything; without the flag meshes
  are not kept and the archive is byte-identical.
- `tests/parity.rs` holds built-in capabilities to parity with their re-expressions on the pinned public models (`fixtures/parity`), through `check --geometry --rule-status`; it is ignored unless `AXIOVAL_PARITY_MODELS` names the fetched models, and then fails on any difference a case's `parity.json` does not record and on any recorded one no longer shown. Its non-ignored test compiles every case against the registry and checks every `recorded` rule has a recording for each model. A case's `recorded` rules (capabilities replaced by templates) are compared with the outcomes the replaced implementation reported, stored in `recorded/<model>.json`; `AXIOVAL_PARITY_RECORD=1` rewrites them, only before an implementation is replaced, never to make a difference disappear. Record a divergence with its reason and decision; never widen a comparison to make one disappear.
- `benches/templates.rs` is the template benchmark (#279, `docs/src/performance.md`): each `PAIRS` capability's rules run by the default registry and by one with its reference in its place (`CapabilityRegistry::replace`), on a generated fixture and the public models, meshed by this crate's `geometry.rs` (included by path; never fork it), held to `Parity::contract()` first. Its peak heap comes from the bench-only `peak_alloc` global allocator. `scripts/bench.py` runs and judges it; never fold it into `cargo test`. Its records list every run of both sides in order (`times_ns`, `peaks_bytes`, run `i` of each side paired) and `--only FILE` measures just the named `[capability, input]` pairs (a gate's further rounds, #293); keep both additive.
- `tests/check.rs` runs the real binary; keep a case for every exit status. Update `docs/src/cli.md` with any change to arguments, output or status.
- `check --locate` builds the IFC `LocationPolicy` (`IfcBuildingStorey`, `IfcSpace`, containment and aggregation, `Name`); `none` must leave the result byte-identical. `report --location` keeps outcomes whose location is unresolved.
- `check` identifies every finding with `Report::identify_findings` over
  `bcf::IFC_GLOBAL_ID_SCHEME`, the scheme the BCF sink keys topics by, so a
  decision and a topic GUID are one key. `--decisions` applies a decisions
  file (loaded before the run, so a bad file fails before any work);
  decisions never change the exit status. `decide` writes the decisions
  file with each finding's basis and writes nothing when any `--finding` is
  not in the result. `report` prints ids and decisions, counts them in the
  summary, lists stale ones as the `stale-decisions` section and filters by
  `--decision`.
- `check --decisions-from ARCHIVE` reads the BCF bytes before the run (a
  missing file fails before any work), imports them with `bcf::import`
  after identification and applies the decisions; it conflicts with
  `--decisions`. Unmatched topics go to the additive `unmatched_topics`
  field (`digest::UnmatchedTopicRecord`), the `unmatched-topics` section and
  one stderr warning; they never change the exit status. It imports with
  the run's `rule_labels`, so the export's own labels are not read back as
  a reviewer's.
- `decide --assign-to/--due/--priority/--label` keep their earlier values
  when a later decision does not restate them, and `--comment` appends to
  the finding's thread, never replaces it.
- `src/server.rs` is `axioval bcf push` and `pull`. It rebuilds the project
  from the result's `objects` (kind and GlobalId of every object the report
  names; resource objects stay with the report) and maps topics only
  through the sink and `axioval-bcf-api`. Credentials come from
  `AXIOVAL_BCF_TOKEN` or `AXIOVAL_BCF_CLIENT_SECRET`, never from arguments,
  and are never written. `tests/check.rs` includes the API crate's
  in-process server by path; never call a real server. HTTPS only with the
  `tls` feature.
- `--xlsx` (shared by `check` and `compare` through `OutputArgs`) writes
  `axioval-xlsx`'s workbook with the GlobalId scheme as the external
  identity column, created at `SOURCE_DATE_EPOCH` or now
  (`epoch_seconds`). It is built with every other output before anything
  is written; `tests/check.rs` reads two takeoff sheets back.
- `--html` (shared through `OutputArgs`) renders `axioval-html`'s report,
  dated as BCF topics are (`timestamp`). `--html-template` is read and
  parsed by `OutputArgs::prepare` at the start of `check` and `compare`,
  so a missing or refused template fails (status 1) before any work.
  Never run anything from a template; never print a PDF here.
- Packages are read only through `load_ruleset` and `load_definitions` in
  `main.rs`, which load the table files they name from the directory
  holding the package file; never parse a package with `load` alone, or a
  `tableFile` parameter reaches the binder unloaded.
- `check` reports every end of a declared relation's listed pair that names
  no single object (`unknown_relation_objects`, taken before the run) as an
  integrity record `relation-object-unknown` (warning, locator
  `axioval:derived.relation;id=<id>:pairs#row=<n>`); it never changes the
  exit status, the rules it leaves undecided do.
- `check --relations RELATION=FILE[#SHEET]` (`relation_arg`,
  `supply_relations`) reads each file with `SuppliedPairs::read` and
  supplies it to the plan right after compiling, before any model is read:
  an undeclared or non-supplied relation, a second file, an unreadable,
  oversized or refused file fails with status 1 and writes nothing. Each
  file is recorded in the additive `relation_files` field
  (`digest::RelationFileRecord`: relation, file name, SHA-256, pair count),
  and a supplied relation given no file is the integrity warning
  `relation-pairs-not-supplied`; its rules are not evaluated, never run
  over an empty relation.
- `check --timings` prints each phase's time on stderr as it ends (`geometry/timings.rs`, `Stopwatch`; rules through `Runtime::with_rule_observer`) and never changes the result or status; `tests/check.rs` pins it. Envelope declarations (`IsExternal` of every meshed object) are read on the first envelope membership request (`LazyEnvelope`), never eagerly: a ruleset without an envelope rule resolves none (the same test).
- `check --rule-status` records `Report::rules`; the summary lists them bounded by `--top` (rules that did not pass first) and never changes the exit status.
