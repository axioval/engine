# `axioval-engine`

Trusted capability registration, strict package binding, typed host services, execution plans, and deterministic runtime orchestration.

Packages are untrusted data. Unknown definitions, capability/signature drift, unknown parameters, missing required values, and type mismatches fail compilation. A parameter its definition fixes (`fixed`) binds to its default: a definition package fixing one without a default fails (`FixedWithoutDefault`), and so does a rule instance stating one (`FixedParameter`, the MCS binder's message), never silently ignored; only a new definition changes it. A `table` parameter's columns are part of the signature: the definition must declare the descriptor's columns by ID, kind and requirement, and every bound or defaulted row must fit them (no unknown column, no cell of another kind, no missing required cell), or compilation fails. Capability execution returns `CapabilityEvaluation`; missing services or unusable evidence belong in typed not-evaluated outcomes, never an empty-findings false pass. Runtime attaches the compiled rule identity and sorts report outcomes deterministically. `compile_rulesets` compiles each ruleset exactly as `compile` does and only then qualifies its rule ids by package (`QUALIFIED_RULE_SEPARATOR`); one ruleset keeps its ids. Never let one ruleset's definition packages resolve another's rules. Report tables (`push_table`) are bound to the compiled rule, sorted by rule and name, and a rule reporting one name twice fails the run; a table never replaces a finding or a not-evaluated outcome.

`catalogue.rs` builds the authoring catalogue (`axioval catalogue`) from the registry, the IR tables, `UNIT_SYMBOLS`, `DERIVATIONS` and `RelationshipKind`. It refuses to build when a registered capability, a parameter or a measured value lacks English and German texts; keep it that way, so nothing is offered to an editor undescribed. The unit parser and the derived-relationship parser read the same tables the catalogue lists, so the two cannot drift. Every package definition it lists carries `available` (`DefinitionEntry`), decided by `compiler::bound_capability`, the check `compile` binds every rule with; never decide it another way, and never drop an unavailable definition or fail the catalogue over it.

`comparison.rs` is the one comparison every rule decides with: numbers as intervals (`numbers`, through `verdict`, exact or under a `Tolerance`), integers, truths, folded and trimmed text, whole-value patterns and dates on XML Schema's timeline (`temporal_order`). The evaluator, the rules crate's selectors and judges and the templates' decisions all call it; never add a second ordering of values, and keep wording with the callers (it returns structured failures). `template.rs` states built-in capabilities as templates: data (descriptor, declaration checks, services, message texts, forms of values and a decision) the rules crate's runner interprets; `RuleCapability::template` exposes it and the catalogue lists it (`CapabilityEntry::template`, each form's `requirement` with its block tree). Keep it data: no closures, no per-capability code, nothing a package supplies. `Form::requirement` and `Decision::expression` are the expression form an editor expands and a rule forks into; a new `Decision` needs one. `Decision::Compare` (`Comparison`) is the generic comparison judge: an operator word against one target parameter, each target with its kind and admitted words. `ROUNDING_ULPS` is the one rounding allowance (`rounding_slack` in the rules crate reads it).

`draft.rs` checks one rule or expression draft within a ruleset context by compiling the context as `check` would, and turns the first refusal into a `Diagnostic` (code from the error's variant, the engine path, a JSON pointer into the draft through the catalogue's field tables, a nearest-name suggestion). Never compile drafts another way, so a draft that validates is exactly one that runs. `ExpressionTraces` is opt-in: without it a run records nothing.

`table_files.rs` owns table parameters read from package data files (`ParameterValue::TableFile`): `load_table_files`/`load_definition_table_files` read each through a host's `PackageFiles` (`PackageDirectory` refuses paths resolving outside its root and files over `TABLE_FILE_LIMIT_BYTES`), check the path, the declared SHA-256 and the declared columns, and parse a CSV file or a named xlsx sheet into typed rows held beside the reference (never serialized). Everything fails closed: a header missing a declared column or naming an undeclared one, a cell not of its column's kind, a formula or error cell (never its cached value). The compiler (`bind_table_file`) refuses an unloaded reference and declared columns that are not the table's (unknown, another kind, a required one missing) with `InvalidTableFile`, then binds the rows as the inline `Table` they are, so capabilities never see a file. Never execute or evaluate anything a file holds, and never default a cell.

`properties.rs` owns exact source-neutral property requests, request-bound present values and absence proofs, response validation, and the typed property-resolution service handle. Every conclusive response must bind the complete request, including the source-qualified object identity; matching property names alone are insufficient. Missing object-map entries are not evidence of absence. Source interpretation and completeness proof stay in providers. `PropertyResolutionError::UnreadableValue` (an `UnreadableValue`: request, exactly declared type, exact evidence, reason) is the one error that is also an answer: the property is present with a stated value of that type that cannot be read. The handle binds it to the request and checks its evidence; capabilities that do not read it stay not evaluated, and none may compare its value. It also owns property enumeration (`PropertyEnumerationRequest` with a `NameMatch` per set and name: any, exact, or a whole-name `NamePattern`, and `PropertyEnumeration`, sorted, distinct, every property selected by the request and exact, with completeness evidence, and `empty_sets`: the selected sets the object carries without any member, which `with_empty_sets` validates as selected, not reserved and holding no enumerated property). An empty enumeration is a proof of absence, so the trait's default `enumerate` refuses rather than answer empty; never give it a default that lists what `resolve` happens to find. Enumeration never covers the reserved sets: an exact reserved set is an invalid request, and a pattern never selects one.

`relationships.rs` owns exact comparison-candidate requests and request-bound complete selections. The request binds the checked object, canonical candidate universe, and semantic traversal or shared-group query. The universe is a shared `CandidateUniverse` (#429): build it once per set of anchors and bind each request with `RelationshipSelectionRequest::within`; never copy a universe per request or per hop (`PathSegment::walk_within` takes built ones; `walk` builds them once per call). Its kept parts (`within_sources`) are bounded and dropped with it, and looked up before the universe is scanned. `closes_chains` (#428) is a service's promise that a chain asked from any object a chain answer reached adds no candidate beyond that answer and its anchor and no evidence, and does not refuse; its default is `false`. Declare it only where it holds for every anchor (the IFC adapter's breadth-first closure does); a wrapper forwards it for the identities it passes on and keeps `false` for its own, and a service citing each anchor (stated-first, declared relations, groups, the flow) never declares it. The stated-first router builds the universe it looks through once per answer (the project's once per session), never per step. Providers interpret native relationship structures and must return exact reviewable completeness evidence. Capabilities must not treat the legacy `Object.relationships` map as authoritative. It also owns `RelationshipKind`, the source-neutral kinds answered as `axioval:relationship.<kind>` identities through the same service (a source maps them onto its own relationships and refuses a kind it does not know), and the edges listing (`RelationshipEdgesRequest`, `CompleteRelationshipEdges`): every edge with both ends in the universe, sorted and unrepeated, bound to its request. The trait's default `edges` refuses; never give it a default that answers none or one built from per-anchor selections. The derived router refuses listing derived identities; `path.rs` keeps the colons of `axioval:relationship.` identities as it does `axioval:derived.` ones.

`path.rs` owns the one step grammar every relationship path shares (`PathSegment`: `Relationship[|Relationship…][:direction][+]`) and its walk. A `related` selector, a traversal `path` and a measured `bottom_above_level` path all parse through it; never add a second parser. A step through several relationships with `+` hops between project objects, each hop following any alternative's own chain; `|` is never part of an identity, and one direction after the last alternative applies to all. `walk_from_each` walks a step from a whole frontier: each request answered once (a memo per call), and where the service closes every relationship's chains no chain asked from what a chain of it reached and no start walked that another start's walk reached (#428); its evidence is a union, so callers sort and deduplicate it. `walk_within` keeps asking every chain, as `measured` reads its evidence with repeats. A query answered from the memo is charged as if asked, its citations included (#441). Every walk is refused past `WALK_BUDGET` (`OverBudget`, read by rules as `ResourceLimit`); raise it only with timings.

`derived_relationships.rs` owns relationships derived from geometry: the `axioval:derived.*` identities with their tolerances, the derived-relationship handle, and the routing the session installs over the relationship handle. The handle refuses evidence that does not name its derivation. Derivation algorithms stay in geometry adapters; an unknown derivation or parameter is an invalid request, never an empty answer. It also owns `LevelMatch` (`axioval:derived.same-level`), which is never routed to a geometry provider: it judges two levels' stated facts (`LevelFacts`), `None` when either is unstated, and allows only one unit conversion's rounding beyond its tolerance. The adjacency side locator form read by `adjacent_side` is a provider contract; change it only together with every geometry adapter that writes it. So are `adjacent-across`'s edge and face records read by `across_side`. The router answers `adjacent-across` stated-first (`StatedFirst`): an element with stated `space-boundary` edges anywhere in the project is answered from them alone (cited `{identity}:stated:{element}`, `across_stated`), geometry only for an element stating none; a refused stated answer refuses, never falls back to geometry.

`network.rs` owns distribution networks: `DistributionNetworkService` (adapters list each source's `axioval_ir::DistributionNetwork`, refused for a source they do not cover, never answered empty; federation routes it by source), `FlowGraph` (elements joined by their connected ports, flow from a `source` port's element to a `sink` port's, through a named realizing element) and `axioval:derived.flow`, installed over the run's relationship handle before any rule when either service is registered, beside `Arc<FlowGraphs>` (one graph per source per run, shared by the flow and the `fall_in_flow` provider; `FlowGraph::ports` and `settled` are what a measurement in flow direction reads). A directed read reaching an undecided connection (no single direction from the two ports) or a cycle of flow refuses with the reason; a connection to a port of no single element refuses every read through its element; `either` needs no direction. An open port reaches nothing and is cited (`open-end:<port>`). Never infer a direction from geometry, names or one port alone.

`topology.rs` owns deterministic source-neutral connectivity and route queries over exact typed evidence. It must not infer edges from source relationships or import geometry, IFC, ICDD, Axiolid, or vendor types.

`metric_routing.rs` owns canonical-metre requests, conservative distance bounds, three-valued threshold comparison, and the backend-neutral service handle. Algorithms and native geometry types stay in Axiolid or another geometry provider. A blocked result requires complete exact evidence; a known route through incomplete topology proves existence only. The many-target queries (`nearest_target`, `farthest_point`) are default methods that refuse; never give them a default that answers from single routes. A nearest answer's interval bounds the nearest of all targets, its target index only names the one its route reaches; a farthest answer's witness lies on the requested region and its `converged` must hold for the requested tolerance. The handle checks all three, and an unreachable answer must carry its own request. A nearest-target request may avoid objects (`with_avoided`); the handle refuses it unless the backend's `avoids_objects()` is true, so no backend answers a detour with the plain walk; never default `avoids_objects` to true. `trace_path` (`PathTraceRequest`, `PathTrace`) measures a polyline over each object's plan footprint as an interval (upper bound with the boundary, lower without) or a per-object reason; its default refuses, and the handle refuses an answer with another object count or a lower bound past the polyline's own plan length. Route, nearest and farthest requests may carry a `ConnectorRouting` (`with_connectors`: typed `VerticalConnector`s, one kind per object, and a `ClimbLength` of a `StairLength` measure and a vertical factor); such a request climbs only through its own connectors, and the handle refuses it unless the backend's `climbs_connectors()` is true, so no backend answers a climb with a walk on one level; never default `climbs_connectors` to true. A route request may walk up to its destination's object (`approaching`: the body's walk to where it stands plus the straight reach to the point, which may lie inside the object's own body); the handle refuses it unless the backend's `approaches_objects()` is true; never default it to true. `ClimbLength::length` bounds a climb from both intervals' ends, rounded outwards. Nearest and farthest requests may carry `TravelCost`s (`with_costs`: an object and a factor of at least one, sorted, the greatest per object kept, ones dropped); the handle refuses them unless the backend's `weighs_travel()` is true; never default it to true. `forced_walk` (`ForcedWalkRequest`, `ForcedWalkOutcome`) brackets the shortest walk to a target entering an object: a finite lower bound, an upper bound infinite when no entering walk is known, or `NeverEntered` under complete evidence bound to its request; its default refuses, and the handle refuses avoided objects without `avoids_objects` and checks convergence against the tolerance.

`free_space.rs` owns source-neutral metric frames, clearance shapes, area bounds, constrained placement searches, and their typed service handle. Keep proof asymmetry explicit: obstruction and placement may use exact witnesses; clear and no-placement require complete exact coverage. Grounded support and frame-offset search predicates belong in requests, and so do the obstacle elevation band (`ElevationBand`, defaulting to the shape's height), merged scopes and an `EntranceReach` (a witness's shape must meet a piece of the free area eroded by half the path's width near an entrance, as a circulation contact; its entrances leave the obstacles and swept doors); clear and no-placement require complete exact coverage. Grounded support and frame-offset search predicates belong in requests, and so do the obstacle elevation band (`ElevationBand`, defaulting to the shape's height) and merged scopes; a frame-offset anchor may be grounded on another object (a door, a fixture), the witness never; every supported found witness also needs exact frame-bound whole-base support evidence. Rasterization, collision, CSG, and search algorithms stay outside the engine. A clearance frame's origin is the centre of the volume's base; keep every backend to it. `estimate_largest_disc` (`LargestDiscEstimate`, #400) is a hint for where a search of the largest shape should look, never evidence: its default refuses, the handle passes it through, and a caller states a size only from `find_placement` searches. `ContainmentRequest` asks whether a volume's plan lies inside the union of scopes; `Inside` and `Outside` are both whole-footprint claims, and the trait's default refuses rather than answering either.; `Inside` and `Outside` are both whole-footprint claims, and the trait's default refuses rather than answering either. `SupportCoverageRequest` asks the same of the supports' upward faces within an elevation band (`Supported`/`Unsupported`, exact request-bound `SupportCoverageEvidence`); its default refuses too, and the handle refuses an answer to another request.

`circulation.rs` owns the circulation-map contract (`CirculationRequest`, `CirculationMap`) answered by `FreeSpaceService::map_circulation`, whose default refuses. A map is a measurement, never a verdict: pieces lie inside the exact erosion of the free area by half the path width (proof of connection), possible pieces contain it (proof of separation); keep both bounds and never merge them into one region. Node positions are approximate; only a node's piece and its half-width bounds are proven, so nothing may be decided from a node position alone. `try_new` validates the map's shape (kinds against neighbours, edges within a piece, one contact per subject); the handle binds it to the request. A request may merge scopes (never obstacles, never an entrance or component) and start its band above the floor.

`object_frame.rs` owns object placement frames and stated fronts. A frame is grounded on the requested object and carries exact reviewable evidence from its source; a front is `Stated` only where the source states one and is never inferred from axes, shape or type. `forward` is a placement axis, not a front.

`door_leaves.rs` owns door leaves and window panels (the types keep their door names), answered by `ObjectFrameService::leaves`, whose default refuses (`Unsupported`); the federation router forwards it. Leaves are derived from what the source states, so their evidence is exact; a source stating too little is `NotStated`, never defaulted. A source stating one swinging or double-acting leaf and its width but not its place along the opening answers `DoorLeavesError::Unplaced` with an `UnplacedLeaf` (#378: overall width, lining, width, depth, exact evidence, the refusal's words as its `Display`): every consumer needing the place reads it as a refusal, and only a width independent of the place (the clear width from the leaves) may read the leaf. The handle refuses one for another door. Never give an unplaced leaf an origin, axes or a swing. A leaf's axes are orthonormal but may be left-handed, so they are never a `MetricFrame`. A hinged leaf (`Swing`, `DoubleSwing`, `TiltAndTurn`) has both a hinge side and a `SwingSector` whose radius is its width and whose `open` is its opening direction; no other leaf has either. A tilting leaf (`TiltAndTurn`, `Tilt`) has a height and a tilt sector whose radius is its height, whose `open` is its opening direction and whose `closed` runs along `up`; `DoorLeaves::try_new` refuses one without it. Height and tilt are builder methods so door sources stay unchanged. `SwingSector::plan_bounds` is the one polygonisation of a sector (inscribed and circumscribed, anticlockwise); keep every consumer on it. `SweptDoor` is a door's horizontal swing sectors as an obstacle (placement, circulation and walkability requests take them with `with_swept_doors`, sorted, one door once, else `ConflictingSweptDoors`): a witness, piece or definite passage keeps clear of the circumscribed polygon, a proof of absence, possible piece or separation holds against the inscribed one; a sector counts only on a floor it `stands_on` (hinge at most `SWEPT_FLOOR_REACH_METRES` below it and below the band's top). Never measure a swing from a door's body. An entrance is walked through: circulation drops its swing, walkability never counts it against a passage through that portal.

`session.rs` owns immutable project/source snapshots and the session-authoritative service registry. Every session service must implement `SnapshotBoundService`; reject unbound, duplicate, unknown, or non-identical source/revision/fingerprint/schema bindings before registration. A snapshot without objects is an empty source, never an error; only an object without a snapshot or a source twice is refused. It also holds each source's declared `Discipline`, beside the snapshot and never in its identity, which the runtime installs per run as `SourceDisciplines` (replacing any host copy, like `ConceptBindings`), and the runtime installs every snapshot's source the same way as `SessionSources`, so a capability judging each source never loses an empty one. `discipline_map.rs` owns `DisciplineMap` (ordered wildcard rules over one metadata field each), `DisciplineOrigin` and `UnmappedReason`, and the one `like` wildcard translation (`wildcard_regex`). A map assigns only to sources declaring no discipline, first matching rule wins, and a rule reading an unread field stops the search (the source keeps none): never skip a rule that might have matched. Every mapped discipline keeps its origin (rule and value) through federation and into `SourceDisciplines`. `source_metadata.rs` owns `SourceMetadata` (per field: unread, or read completely with every distinct non-blank value, possibly none) and `SourceMetadataIndex`, which the runtime installs per run like `SourceDisciplines`, filling `schema` from the snapshot unless stated. Metadata is never part of a snapshot's identity; `with_source_metadata` adds fields up and refuses a field stated twice with other values (`ConflictingMetadata`), never picks one.

`resources.rs` owns resource objects: `ResourceService` (a source's instances of one class that are not its objects, complete or refused; an object class and, with subtypes, a class with an object subclass have none), its handle (refuses uncovered sources, foreign instances, instances with facts of their own, and unsorted or repeated answers), and `ResourceObjects`, which the runtime installs before any rule runs (replacing any host copy) from the `entityType` classes of the rules' applicability selectors, bound per source and asked once per source and class; an answer naming a project object is refused. Resource objects are never part of `Project` or `Project::objects`; a population reaches them only through `ResourceObjects::reached` (`entityType`, `allOf`/`anyOf` operands, and `ruleOutcome` through the named rule's record), never `all`, `not` or any other selector. A class no rule names is never listed. The runtime puts the resource objects a report names into `Report::resources`; `rule_outcomes::selection` judges the reached resource objects too, and a record keeps the sources whose resource objects could not be listed.

`coordinate_system.rs` owns source coordinate systems: the world frame, true north and map conversion a source states, each `None` when unstated and never defaulted, and the site placement (`SitePlacement`), `Unknown` unless the service states it (`with_site`), never `Absent` by default. A map offset's metres per unit is `None` unless the unit is known exactly. The handle refuses uncovered sources and answers about another source. `MapPlacement::of` is the one check that a source's map conversion places map coordinates in its model coordinates (a conversion, onto the stated reference system by `same_reference_system`, an exact map unit, a world frame stated as the identity, a scale within `MAP_SCALE_TOLERANCE` of one); context zones and the terrain both place through it, and its `MapPlacementRefusal` says why not.

`alignment.rs` owns positions along alignments: `AlignmentRequest` (an object and an alignment, never the same), `AlignmentPosition` (plan distance to the reference point's foot, station, offset positive to the left, height above the gradient line) and `AlignmentParameterValue` (curvature, gradient or cant over a stretch of plan distances; only cant may be none, an alignment stating none). Every value is an `AlignmentInterval` sure to hold the exact one, and evidence is exact exactly when every interval is a point. A foot before the start or beyond the end is `OffRange`, never clamped to an end; feet that cannot be told apart are `Ambiguous`, never one picked. `measure_alignment_parameter` refuses by default; never default it to a straight, level, uncanted line. The handle refuses an answer about another request. `measured/alignment.rs` answers `station`, `offset`, `height_above_gradient` and `alignment_*` through it: the alignment is the one object of the `alignment` kinds the `path` reaches (or in the object's source without one), none an exact absence, several refused; `alignment_radius` is refused where the curvature interval holds zero, and `alignment_vertical_radius` where the vertical curvature's does (`AlignmentParameter::VerticalCurvature`, `z'' / (1 + z'^2)^(3/2)`, positive in a sag): a straight has zero curvature and an unbounded radius, never an infinite or defaulted one.

`alignment_element.rs` owns the elements of an alignment's layouts: `AlignmentElementsRequest` (an alignment and a horizontal or vertical `AlignmentLayout`) answered by `AlignmentService::measure_alignment_elements` (refuses by default; the handle refuses an answer about another request) with `AlignmentElements`, each `AlignmentElement` its source-neutral kind, the source's type name, stations, stated length, an `ElementEnd` at each end (straight, a signed radius, or unread with the reason) and a vertical element's gradients; evidence exact exactly when every station is a point. Curvatures, radii and the clothoid parameter (`A^2 = L / |k_end - k_start|`) are derived there as intervals, never accepted from an adapter; an unread end leaves everything derived from it undecided, never a straight. `measured/elements.rs` (`AlignmentElementMeasures`, registered by `axioval-rules`) lists them as the member list `alignment_elements`: a straight end's radius is undecided, a value the element does not have (an arc's clothoid parameter, a plan element's gradient, a transition's one radius) `null`. `element` is the first text field, so `pairs` names a pair by it.

`material_layers.rs` owns material layers (#334): `MaterialLayerService::material_layers` (`// gate: reads`, stated facts) answers an element's `MaterialLayers` in the source's order with an optional `LayerDirection` (a `LayerAxis` of the element's placement frame and a `LayerSense`, from the first layer to the last); exact evidence only, no material an empty list, any other material `NotLayered` by name, never read as layers. It is a semantic service: federation routes it by source (`routed` and `register`). `measured/layers.rs` (`MaterialLayerMeasures`, registered by `axioval-rules`) lists it as the member list `layers`: the inside is the face beside which objects of the `spaces` kinds lie when none lies beside the other, from the derived service directly (`across_face`, never the stated-first router, whose stated answers record no face), and the stated direction's cosine with that face's outward normal (at least `ALONG_NORMAL`, 45°) decides whether the first or the last layer is innermost. Anything undecided lists the layers in the source's order with `position` and `from_inside` undecided and the reason; never order them by a guess, never default a direction, and keep every stated field readable. `layer` is the first text field, so findings name a layer by it.

`station_profile.rs` owns station-parameterised values: `AlignmentProfileRequest` (an alignment, a parameter, an optional station range and step) answered by `AlignmentService::measure_alignment_profile` (refuses by default) with an `AlignmentProfile` of contiguous `ProfilePiece`s, each its start station, its values at both ends and a rate interval holding every derivative over it. The rate is the sampling certificate: an extreme is exact only where the rate keeps one sign, else bounded where the two rate lines from the ends meet; never accept a piece without a rate bound or interpolate between samples. `magnitude` splits where a value crosses zero (the crossing stretch takes every rate of either sign). `rates` is the hull of the pieces' rates (at a seam both one-sided derivatives), `difference_rate` the change between the stretch's ends over its plan length, `rate_extreme` bounded below by every piece's rate lower bound and mean slope; never report a rate the pieces do not bound. `measured/profile.rs` answers `max_along` and `min_along` (with `rate=true` of the rate) and `rate_along` (at `station`, or over `over`) on an alignment, naming the stations in the evidence.

`section.rs` owns sections across alignments and clearance envelopes swept along them, answered by `AlignmentService::measure_section` and `measure_envelope` (both refuse by default; the handle refuses an answer about another request). A `BodySection` is an interval region in `(lateral, up)`: the mesh's oriented cut, the band of mesh pieces within `radius` of the plane projected onto it, and the radius; surely inside means in the cut and farther than the radius from the band, possibly inside in the cut or within it. Area and extents are derived here from that region, never accepted from an adapter, and keep its interval; evidence is exact exactly when every radius is zero. An `EnvelopeSweep` gives one `Intrusion` per requested body in order (`Sure` with its proving distance, `Possible` with the reason, `Clear`), evidence exact exactly when none is possible. `Clear` is a proof over the whole swept volume, never a sampling result: a service must bound the envelope's motion between samples and leave a body it cannot decide `Possible`. `measured/section.rs` answers `station_section_area`, `station_section_thickness` (none where the plane surely misses the body) and `envelope_intrusions` (on an alignment, over the `bodies` kinds in its source; a count from sure to possible, none selected an exact zero, a refusal for the whole value); never turn the count into a point while a body is possible.

`sight_distance.rs` owns sight distances along alignments: `SightDistanceRequest` (an alignment, the eye's station, eye and target as `(lateral, up)` in the section, both strictly above the gradient line, a positive range and step, obstacles sorted and never the alignment) answered by `AlignmentService::measure_sight_distance` (refuses by default) with a `SightDistance`: an interval proven clear up to its lower bound and proven blocked at its upper bound, never above the range (the measure is capped there), naming what blocks it (`SightObstruction::GradientLine` or a requested `Body`) whenever the upper bound is below the range. The handle refuses another request's answer and a body the request did not send. `measured/sight_distance.rs` reads it as `available_sight_distance` on the alignment, obstacles by kind in its source. Never report a clear sight line that was not proven; terrain enters only as a selected body.
`terrain/` owns terrain as context beside the model: `TerrainService` (`surfaces`; `measure_elevation` at a `TerrainPointRequest`; `measure_mean_elevation` along a `TerrainOutlineRequest`'s rings, refused by default) and its handle, which refuses a `TerrainKind` the service does not serve (`NotSupplied`) and an answer about another kind or with another accuracy than the surface states. Every `TerrainElevation` is widened by the surface's stated vertical accuracy (`try_new` refuses one narrower than twice it, and an exact one with any accuracy); never assume an accuracy, and never answer one ground for the other. A plan point no triangle holds is `Outside`, one held at two elevations `Folded`; never answer from the nearest edge or pick one. `tin.rs` holds `TerrainSurface` (points stored about their plan centre, a uniform grid index) and `TinTerrain` (one surface per kind); the mean along rings is exact for the TIN (cut at triangle edges, trapezoids), a piece outside refuses by its midpoint, and an outline deviation widens it by the steepest gradient crossed. `landxml.rs` reads one LandXML `TIN` surface through `table_files::walk_document`: `northing easting elevation` points, invisible faces left out, a stated linear unit only, the named coordinate system kept for a map surface only. A service answers in its own coordinates (`TerrainFrame`); placing a model point on a map surface is the reader's. `Runtime::with_terrain` installs the host's terrain in every run. `terrain_kinds_read` lists the grounds a plan's rules and values read (both where a rule binds `terrain` from a parameter), for a host to warn of one not supplied. `measured/terrain.rs` answers `above_terrain` and `mean_terrain_height`: the outline through `PlanAreaService::measure_footprint_outline` (`FootprintOutline`, the outer rings of the union of objects' footprints with their chord deviation, exact exactly when it is zero; its default refuses, never a bounding box), a map terrain placed through the source's stated map conversion through `coordinate_system::MapPlacement` (the one placement context zones use too; never check a map conversion another way) and refused, never guessed, where `MapPlacement::of` refuses; every value is the object's interval less the terrain's, rounded outward. `validate` refuses `reference=beneath` but `of=point`, `path` but `of=level` and `outline_path` without `outline` at parse time.

`local_origin.rs` owns `LocalOrigin`/`LocalOrigins` (#372): a host measuring a source's geometry in its model coordinates less a horizontal translation registers them with `EvidenceSession::with_local_origins`, which also answers object frames and door leaves in that frame (`ObjectFrameServiceHandle::in_local_frames`). Context zones are placed into it (`ContextZone::place_in`), terrain placement and the `x`/`y` values move points back (`to_model`, `to_model_bounded`), and rules report positions through `axioval-rules`' `support::local_origin`. `federation.rs` routes a federated session's semantic services to the member owning each request's source. Edges of a declared relation are never listed. A `supplied` relation's pairs come from the host per run (`SuppliedPairs`, read with the table-file reader by `compiler::supplied_columns`, the relation's declared or default `from`/`to` columns; `ExecutionPlan::supply_relation` checks them with the listed rows' `check_pair_rows`) and are derived exactly as listed pairs, their evidence citing the file's digest (`:pairs;sha256=<digest>#row=<n>`). Without supplied pairs the relation sets `all_forward` and `all_backward`: every walk is undecided, never an empty relation.

`catalogues.rs` owns catalogues of material and product data (`CatalogueDefinition`; not the authoring catalogue of `catalogue.rs`): the compiler checks each declaration (`check_definition`: id, a declared `string` key column, value columns only, units it reads; `merge_catalogues` across rulesets), the host supplies entries per run (`SuppliedCatalogue`, read with the table-file reader; `ExecutionPlan::supply_catalogue` checks every cell's kind and unique non-blank keys), and the runtime installs `Arc<Catalogues>` from the plan (replacing any host copy) before derived values, which read it too. `Catalogues::read` is the one join: exact key equality, an empty cell `null`, a key without an entry or an unsupplied catalogue unreadable naming the key, never a default; the evidence locator (`CATALOGUE_LOCATOR_PREFIX;id=…;version=…;sha256=…#entry=…`) is a contract, so a catalogue value is always told apart from the model's. Types come from the declaration (`expression_binding::catalogue_types`, carried in `DeclaredTypes`). A results catalogue (`CatalogueDefinition::results`, #323; `check_results`) is read only where the entry states method, report, date and revision and the revision names the reading object's model (`ModelRevision`, per source in `Catalogues`, `ExecutionPlan::supply_model_revision`: `sha256:<hex>` of the file or the stated revision); untraceable, unmatched (no revision stated) and stale entries are unreadable with the reason, never read as another model's, and `stale_results` lists them for the host. The provenance follows the entry in the locator (`;method=…;report=…;date=…;revision=…`, `locator_text` percent-encodes `%;#=`). A catalogue stated per range (`CatalogueDefinition::ranges`, #324; `check_ranges`, `index_ranges`: both ends stated, start below end, no overlap per key) is read only through `Catalogues::read_at` (`ExpressionContext::catalogue_at`, the `catalogue` node's `at`): the ranges `[from, to)` an interval position reaches must cover it and state one value, else it is unreadable naming them, never the nearest range or a picked one; each range cited `#entry=<key>;range=<from>..<to>`. The type checker takes the position's unit from the `from` column (`TypeEnvironment::catalogue_ranges`, `DeclaredTypes::with_catalogue_ranges`).

`context_zones.rs` also reads a GeoJSON feature's `properties.values` (#324, `stated_values`): text (`ZoneValue::Text`), plain numbers, quantities (`ZoneValue::Quantity`, as stated), the neutral keys kept in their dimension and coherent units; anything else refuses the file. `zone_reads` counts the `zone` and `standsIn` of every `zone` expression. The `zone` node (`ExpressionContext::zone`, `ZoneNamed`) is answered by the rules crate; the core's derived values do not read it.

`compartments.rs` derives `compartment` groupings: joins across plain separators read from `DerivedRelationshipServiceHandle` (geometry only, faces by `across_side`, never the stated-first router), direct contacts from `ProximityServiceHandle` over `candidate_pairs`, regions by union-find keyed by their least member. A possible join undecides both regions; a plain or undecided element whose faces cannot be read, a member without extent and a missing service undecide every member. Never split a compartment on an assumption.

`measured.rs` owns `axioval:measured`: each name answered by one geometry service (vertical extent, directional extent, footprint, body volume), exact exactly as the service's evidence states (`Answer::Value` carries it; never infer exactness from a point, which a tessellation measures too), an exact point as a quantity, anything else as `PropertyValue::Measured` with located evidence (the property handle admits exactly that), sums, differences and shares rounded outward (`span`, `bounds`), a missing service as `PropertyResolutionError::MissingService` (the runtime collapses object-level missing services per rule and source). Never answer a measured name from a mesh the service did not certify, and never turn an interval into a point. Every measured name is declared in the registry `axioval_ir::measured` (`MEASURED_VALUES`) and parsed there; `measured::parse` only turns the registry's arguments into engine types (path steps), and the compiler refuses what it refuses with `EngineError::InvalidMeasured`. Never parse a measured name anywhere else; keep the path a rule's parameter, never a host default. A name naming a rule parameter or the anchor (`@name`, `@anchor`) is refused by `measured::parse` (the property-resolution route and `read_batch`); it is read only through `MeasuredValues::read_bound_batch`, with every reference bound by the reading rule, memoized in the run's `MeasuredMemo` by object, name as written and bound arguments, and carries what the provider cites (`MeasuredProvider::measure_cited`, `Citation`). The compiler type-checks references in rule expressions (`expression_binding::references`), and an expression definition may declare `selector` authored parameters for them. `measured/faces.rs` owns the face a surface value reads: `top`/`bottom` from `measure_face_normals`, `face=facing` from the `Boundary` pieces whose every part surely faces the direction within the tolerance (interval cosines; a piece that may or may not face it refuses the value, never dropped or kept on a guess), and `FacePieceMeasures`, the member list `face_pieces` (registered by `axioval-rules`), where such a piece is an uncertain member. A piece's slope, area and direction of descent are derived there, never accepted from an adapter. `level_height` is the source's and is forwarded to the host resolver. `MeasuredValues` (installed by `derived::install`, sharing the run resolver's `Measures`) reads one measured name of many objects at once (`read_batch`, through each provider's `MeasuredProvider::measure_batch`) and must answer exactly the value and evidence resolving each request would (`Measures::read` is the one conversion behind both). `MeasuredMemo` is the run's memo of measurements (installed empty by every run with the providers, never shared between runs): a provider keys an entry by everything the measurement depends on, never by a rule. Its shared table is a view of the run's `DerivationStore` (single flight); keep it one, never a second table beside the store. Parsed names are kept per process (`PARSED`); parsing must stay a pure function of the name. A provider states exactness by the variant it answers: `Measurement::Value` is never exact, a point included; `Measurement::Rounded` keeps exact evidence (its interval only rounding); `Measurement::Cited` is exact as its `exact` says (a tessellation's triangle count is `PropertyValue::Measured` with inexact evidence, a point included). A member's fields are exact as `MeasuredMember::exact` states unless cited inexact. `axioval-rules`' `tests/measured_exactness.rs` holds every registered provider to approximate evidence through `CapabilityRegistry::measured_providers`; register no provider without naming its test there. An item a member list leaves undecided for a reason of its own states that reason in its own text field, read through `Items::reason`; never relabel an undecided field. `values.rs` answers a number computed from any inexact read as `PropertyValue::Measured`, never an exact quantity.

`rule_outcomes.rs` owns rules that read other rules' outcomes: `RuleGate` conditions and `ruleOutcome` selectors, their dependency order and the `RuleOutcomes` the runtime installs before every rule (replacing any host copy). The compiler resolves every reference within its ruleset (an unknown rule, the rule itself or a cycle is `InvalidDependency`), orders the plan so a rule follows the rules it reads (`ExecutionPlan::evaluate_in` reorders the rest for the determinism gate, #441, keeping every rule after the rules it reads, from the plan's `dependencies`; ties by id; `compile_rulesets` renames references with the package), narrows object gates into the applicability selector (gates first), and defers a rule reading a disabled or deferred rule. A whole-rule gate reads the parent's status only; an undecided parent (no finding, something not evaluated) leaves the child one project-scoped `IncompleteEvidence` outcome, a closed gate skips it (`RuleStatus::Skipped`, and a skipped rule passes and fails no object). Per-object reads need the parent's applicability selection, recorded through `OutcomeRefiner::evaluate_selector` (whose default decides nothing): a finding's subject failed; an object left open, or selected in a source or project reported about as a whole, or of undecided selection, is undecided, never passed. Record outcomes after refinement and before collapsing, so per-object outcomes keep their objects. An `auxiliary` rule runs and records its outcome like any other but reports nothing (no findings, tables, not-evaluated outcomes or summary); it reaches the report only through the rules that read it, so the compiler refuses one no enabled rule reads (`InvalidDependency`). Never let an auxiliary rule's undecided objects become decided in its readers.

`expression/` owns the expression language's engine side: `unit.rs` (the one unit algebra; `inUnit` restates a value by it, never another way), `text.rs` (the canonical text form; takeoff computed columns parse through it), `interval.rs` (sound interval arithmetic: round outward where a float operation rounds, keep exact points exact), `table.rs` (a table parameter read between its rows: an interval key reads the hull over its ends and every grid line within, a key beyond the rows is not evaluated unless clamped, never extrapolated), `evaluate.rs` (Kleene truth over true, false and `null`; `evaluate_untraced` is `evaluate` without recording the explanation, never another semantics, not evaluated apart and outranking `null`; a comparison with `null` is `null`, never false; paths into the expression, every leaf read recorded) and `types.rs` (type and unit inference with the same paths). The plan carries the compiler's `DeclaredTypes` and the runtime installs them, so an evaluation types a sum over no member exactly as `types.rs` does; never type it another way. A straddling or undecidable value is never a pass, and neither is `null`: never read a stated absence as false anywhere (aggregates included), so an author's `isDefined`, `isUndefined` or `coalesce` is the only way past one; an `if` on an undecided condition decides only when its branches agree. `extreme.rs` decides `argmin`/`argmax`: every member that may be the extreme is chosen (an undecided member never bounds another, a `by` not evaluated is always possible), their values must agree or the result is not evaluated, and the context relates the chosen members (`ExpressionContext::chosen`); never break a tie by order. `sequence.rs` decides `pairs`: a pair is decided only where every order the intervals of `by` allow keeps its members neighbours (equal points are no order), an undecided pair is not evaluated (`Reason::UndecidedOrder`) and never ordered by a guess, a member of undecided membership makes the pairs bridging it possible, and the context evaluates each pair (`pair_value`, `neighbour` for `previous`/`next`) and relates the deciding pairs (`chosen`). Never add a loop, recursion or anything that runs package code, and never let a capability evaluate an expression any other way.

`expression/budget.rs` owns the expression evaluation budget (#447): an `EvaluationBudget` is one rule's share (or a shared value's build), entered on the thread (`EvaluationBudget::enter`, `budget::current`) by the runtime for each rule and by `Parallelism::map_ordered` on every worker (keep that propagation beside the memory budget's and the store's); `budget::spend` spends the current one, and a context outside a run spends none. A value built once for many readers is built in a share of its own (`budget::built`) and its `Cost` kept beside it; every reader charges it (`budget::charge`, `read_built`) whether it built the value or found it kept: `values.rs`' cache and both `MeasuredMemo` tables do. Never let a kept value charge only its first reader, and never build one in its reader's share. The runtime's `Backstop` (in `lib.rs`) refuses rules whole in plan order once the rules before them spent the budget's size, where they would spend a node or read a refused rule: a rule run in another order (`evaluate_in`) is refused once the rules ahead of it ran, and a rule whose share ran out on several threads is judged again on one. Never re-run a whole check for the budget.

`expression_binding.rs` checks every `expression` parameter when a ruleset is compiled: structure (`Expression::validate`), the concepts and measured names it reads, and its type (a requirement must be a truth), refusing with `EngineError::InvalidExpression` and the path into the expression. A capability answering `takes_authored_parameters` lets its definitions declare scalar, string-list and table parameters of their own; the compiler checks each against the definition's kind and columns, and the capability's own parameters stay strict. Only a capability that evaluates expressions may answer it.

`values.rs` answers `axioval:value`: each ruleset value evaluated at most once per object per install of the run's resolver (`derived::install` starts a fresh cache, so values read the classes and groups derived so far), reading through the run's own resolver with the run's concept bindings, its evidence citing every read. Compilation orders values and refuses cycles (`values::order`); never let a value read a rule parameter. `bound_property_request` in `concepts.rs` is the one place a concept becomes a source request; rules call it too.

`ParameterDescriptor::per_object` marks a parameter a rule may compute per checked object (an `expression` of its kind, or expression cells of a table); the compiler refuses an expression on any other parameter and type checks the rest against the parameter's kind. Capabilities read literals only: `axioval-rules`' `object_parameters::per_object` evaluates, groups objects whose literals agree and runs the capability per group through the engine-internal `Selector::Objects`, which is never serialized. Never mark a population bound (a count over a source, a uniqueness scope) per object.

Every method of a `pub trait …Service` carries a `// gate: measures <kinds>` or `// gate: reads` marker comment above its `fn`; the architecture gate reads the measuring methods from these markers and holds each call of one in a capability to `scripts/measurement_ledger.json` (see `docs/src/contributing.md`). Mark a new method when you add it, never `reads` for one that returns a measured quantity, and keep the kinds to what it actually returns.

`derivation.rs` owns the derivation store of ADR 0006 (#437): `DerivationKind` (a key, a value, a pure `build` reading only its key, other derivations through `Inputs::derive` and the check's services, never a rule's parameters or outcomes; a package never supplies one) and `DerivationStore`, one per run, installed empty among its services (replacing any host copy), where the engine reaches it through the `ServiceRegistry`. Values are kept by kind and key behind `Arc`, keys compared by `Eq` and hashed with `foldhash`, never by a formatted string. A key is built at most once at a time and never under the store's lock: a second caller waits for the build. Keep the three ways a build can end safe: a value lands and wakes its waiters; a panic or an error removes the slot and wakes them, so they build the key themselves; a wait that would never end (the key in the caller's own lineage, reached through other callers' waits, or asked by a worker `Parallelism::map_ordered` started within the build, which inherits the lineage through `derivation::within`) is `DerivationError::Cycle`, never a wait. A failure of the derivation's own belongs in its value. `DerivationStore::forgetful` (`Runtime::without_reuse`, #441) keeps nothing: every read builds, still one build of a key at a time, `put`/`change` are dropped and the memo's per-rule table measures every time; the determinism gate compares it with a keeping store, so never let a value depend on being kept. Statistics (`DerivationStatistics`, #442: the kind's version, hits, builds, waits, build time, releases by name, evictions by `keep_bytes`, `size_hint` bytes held now and at most) are counted under the lock, the build time from a clock around each build only, and never reach a report; `Runtime::with_derivation_observer` hands them to a host at the end of each run (`check --stats` prints them). The runtime also makes the run's store the thread's current one (`derivation::current`, `DerivationStore::enter`), and `Parallelism::map_ordered` enters it on every worker, so a geometry service, which is handed a request and never the registry, derives through it (`DerivationStore::derive_current`; outside a run, built afresh); keep the propagation beside the memory budget's. A kept value's `size_hint` bytes are held against the check's memory budget while kept (`MemoryBudget::hold`, restated by `resize`), and a kind's `keep_bytes` bounds what the store keeps of it, releasing the values read least recently (#408). Release is planned and budgeted (#440): a kind names the service handles it is read through (`DerivationKind::read_through`, `None` for a kind whose readers cannot be told, such as the memo's tables), the runtime takes each rule's services from `geometry_demand::services_asked` and calls `DerivationStore::release_unread` before each rule and after the last, so a kind no rule still to run may ask is released; a store-wide bound (`DerivationStore::keeping`, `Runtime::with_kept_derivations`) and the budget evict the values read least recently store-wide (one clock for every kind) whenever a value lands or grows and what is kept and admitted passes them, sparing the value just landed; and the run registers the store with the budget (`MemoryBudget::reclaim_from`, `Reclaim`), so an admission that does not fit releases kept values before it waits. Lock order is the store's before the budget's: never call into a store while holding the budget's lock (`admit` drops it before `reclaim`). Every release only costs time; never let a value, a refusal or a charge depend on whether it was kept. A new kind's key holds every input its value depends on, its precision class included (#438, #439). A new kind's key holds every input its value depends on, its precision class included (#438, #439), compared field by field (never a `String` key; the architecture gate refuses one), and the kind states `VERSION` (`DerivationVersion`: a revision bumped whenever the same key could build another value, and the kernel crates its build calls at the versions the workspace locks). Every kind in a crate's `src/` has a `KeyCompleteness::<Kind, _>` test in that crate (`derivation/key.rs`), which the architecture gate requires: each input changed in turn must change the key (`input`) and, where it affects the value, the value (`changes_value`); `check` also holds the named kernels to the workspace's `Cargo.lock`. The memo's tables have no version (they keep nothing past a run) and are not under the gate until #443 moves them onto kinds.

`geometry_demand.rs` (#410) also answers `services_asked`, the service handles each rule may ask in plan order (`None`: any), which plans the store's release (#440); it is as conservative as the demand (a measured or derived name in the rule or anything plan-wide makes it `None`), and an error there only keeps a value longer or builds it again. It joins what each rule's capability states it may ask of a host's geometry (`RuleCapability::geometry_reach`: `None`, `Selected` selectors and service types, or `Unbounded`, the default) into a `GeometryDemand` (`Nothing`, `Objects`, `Everything`). It is conservative: an unknown capability, `Unbounded`, or any rule selector or parameter, value, classification, grouping, relation or refinement naming `MEASURED_SET` or `DERIVED_RELATIONSHIP_PREFIX` makes it `Everything`; a selector is bounded by the object types it requires (`AllOf` all, `AnyOf` any, `EntityType` bound through the plan's concepts and the type hierarchy), and anything unbound, unknown or undecided may be selected. A host meshing less than everything watches what it left out: `ServiceRegistry::watch` (`EvidenceSession::watching`) notes every later `get` of a watched type, found or not, on every copy of the registry. `Measures::of` takes its services with `peek` (no note) and notes every watched type when a built-in measured value is read (`Measures::measure`); keep any other code that holds host services the same way, so holding is never asking and using always is.
