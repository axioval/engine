# `axioval-rules`

Maintained source-neutral capability policy and shared rule algorithms.

Capabilities may depend on Axioval IR and typed host-service interfaces, never concrete OpenBIM, ICDD, Axiolid, STEP, or vendor CAD types. Source interpretation belongs in adapters.

`property_rules.rs` owns property compliance policy; `selection.rs` owns fail-closed selector evaluation. Both must resolve property values and absences through `PropertyResolutionServiceHandle`. Never infer absence from a missing `Object.properties` entry, and never silently skip an object when a property selector cannot be resolved exactly. A property selector whose value has another type than it compares is not evaluated, never a non-match; `matches` and `like` match the whole value. A list value is compared only element by element under the selector's `quantifier`, never as a whole; `all` never holds vacuously. A `discipline` selector reads `SourceDisciplines`; a source without a declared discipline is `NotRecorded` with a source-only message (collapsed once per rule and source), never a non-match. A `related` selector walks its `path` with `support::Traversal`; a refused relationship answer or an undecided reached object leaves the candidate undecided, never excluded, and its `all` never holds vacuously either. `property-exists` means exact presence even when a source value is null or blank; `property-required` is the stronger non-empty contract and treats exact absence, null, and blank text as violations without converting adapter failures into findings. `property-data-type` adds the source-declared type to that contract; an unreported type is not evaluated, never a match. Dates and date-times compare only through `support::temporal_order`: dates by day, date-times as instants, and a date-time with a date only at declared `day` precision, never by a default. `property_value.rs` owns `property-value`: lexical constraints cast to the resolved value's kind. A literal or constraint that does not fit the value is not evaluated, never a pass or a violation. `xsd_pattern.rs` translates XML Schema patterns; refuse any construct it cannot map exactly rather than approximate it.

`support.rs` holds the shared parameter reader, exact property resolution, relationship traversal and finding construction; new capabilities use it rather than re-reading `CompiledRule.parameters` by hand. A parameter present with the wrong type is an invalid declaration, never "absent". `support::table` reads table rows and owns row matching (first, most specific, all); capabilities use `match_rows` rather than reimplementing it. It fails closed on undecided rows and reports ties for the most specific row instead of breaking them by order. `property_predicate.rs` and `property_comparison.rs` take exactly one target (none only for the presence operators); keep that check when adding target kinds. `property-comparison` compiles `like` and `matches` with the property selectors' wildcard translation in `selection.rs`, so a word means the same in both; `support.rs` owns the nearest-container climb behind `same_space`/`same_building`. The semantic capabilities (`conformance.rs`, `unique_value.rs`, `consistent_value.rs`, `counts.rs`, `object_count.rs`, `relative_count.rs`, `name_sequence.rs`, `numbering_consistency.rs`, `manual_issue.rs`) read properties, classifications and relationships only. An undecided selector or value is a not-evaluated outcome, and a count is judged only when the undecided objects cannot change the verdict. Test them against the in-memory source in `tests/common/mod.rs`. `plan_area.rs` (`area-ratio`, `plan-coverage`, `plan-area`) and `level_spacing.rs` judge measured intervals: a verdict needs the whole interval on one side of a bound, and a straddling one is not evaluated. `area-ratio` and `plan-area` measure footprints or, with `measure: facade`, facade areas; keep the two behind `plan_area::Measure` rather than a second capability. `level-spacing` measures the highest level from its contents' vertical extents and compares spaces with their level's height; only exact heights decide the prevailing one. `light_area.rs` is `area-ratio`'s `light-area` numerator mode, not a capability: its fallback (stated, table, frame allowance) moves to the next step only on an exact absence, never on an error or a wrong-typed value, and records the step in each area's evidence; keep it a mode so the ratio's judgement stays in one place. `measure: facade` with `light-area` is an invalid declaration.

`table_allocation.rs` (`table-allocation`) assigns each object to one row through `support::table::match_rows`; an object that might belong to a row it was not assigned to (tie, undecided key or selection) leaves that row's count and area not evaluated unless an excess already stands. Never break a tie or skip an undecided object. Its key-cell helpers (`key_cells`, `read_keys`, `test_keys`) are shared with `group_composition.rs`; change them in one place.

`group_composition.rs` (`group-composition`) allocates each group's members to requirement entries by a maximum bipartite matching (`Allocation`), never greedily. Report only what every maximum matching agrees on: competing short entries share one shortfall finding, competing surplus members one surplus finding. An undecided membership, member key or group key leaves the group not evaluated; an ungrouped object is found only when every group that might reach it was walked.

`keyed_limit.rs` (`keyed-limit`) selects one row of a keyed limit table per object with `match_rows` (most specific) and reuses `plan_area`'s footprint and interval judgement. A key it cannot read exactly (absent, blank, another type, reached on no object, or disagreeing across reached objects) is unknown, never a non-match; no matching row is a "no limit defined" finding, and a tie is not evaluated. Its `sill-height` quantity judges the object's bottom against each floor `floor_path` reaches separately, through `level_spacing`'s vertical-extent helpers and `plan_area::judge`; any failing floor is a finding, otherwise an undecided floor leaves the object not evaluated. Keep sill heights a quantity, not a capability, so row selection stays in one place, and keep the elevation difference widened by `difference` so it always holds the exact value.

`property_requirements.rs` (`property-requirements`) checks every applicable row of a requirements table per object (`match_rows`, all rows; an undecided `applies_to` leaves the object not evaluated). Findings start with their result: `missing property`, `missing value`, `forbidden property present`, `forbidden value`, `wrong value`. Set and property names are exact: the property contract cannot enumerate an object's properties (upstream openbimrs/ifc#78), so a wildcard name or a set-only row is refused once per rule, never approximated from `Object.properties` or a permissive lookup. A value condition that cannot judge a value (another kind, a unit mismatch, a straddling quotient) is not evaluated. A `requirement` row is internally a `state` row (`required` = include, `forbidden` = exclude, `optional` = include letting a missing value pass); keep one evaluation path for both. `ignore` rows are skipped before `applies_to` is evaluated and are never refused. `group_by_value` keys groups by row, category, result and the exact `support::value_key`; `category_property` goes through `support::category_prefix`, shared with `property-comparison`, and an unreadable category leaves the object not evaluated. Rounding (`decimals`) reuses `support::round_decimal` in the row's unit; without it bounds stay in canonical SI units so exact values are never rescaled.

`opening_spaces.rs` (`opening-spaces`) judges each door, window or opening by its host's declared exposure. An undeclared, null or non-boolean exposure, disagreeing hosts or no host leave the element not evaluated, never assumed internal. With the derived adjacency it reads sides only through `axioval_engine::adjacent_side`; never parse adjacency locators by hand.

`slab_stack.rs` (`slab-stack-spacing`) pairs slabs by plan-overlap ratio and judges vertical-extent intervals between consecutive slabs, reusing `level_spacing::prevailing` for consistency. An undecided overlap ratio, an unorderable pair of tops, an undecided-selection object that may stack, or any unmeasurable extent is not evaluated; enclosing proximity boxes may only skip overlaps that are provably zero.

`free_floor_circle.rs` and `free_floor_rectangle.rs` own exact grounded vertical-shape profiles. They must request whole-base support and all project objects as candidate obstacles. Missing services, backend failures, and invalid/incomplete proofs emit typed not-evaluated outcomes; they never produce a pass or compliance finding. The rectangle must state its orientation explicitly; never default it to the world axes.

`external_wall_validation.rs` resolves each derivation's bounding objects (`bounding_selector`, or the members of `gross_area_group_selector` along `gross_area_group_path`) and sends them in the `EnvelopeMembershipRequest`; never let the host choose them. An undecided or empty bounding set leaves that derivation not evaluated; each derivation in `derivations` is reported on its own.

`slab_contact.rs` resolves its `counterparts` selector and sends the candidates in every `ContactRequest`; the adapter measures only those. A shortfall with undecided counterparts is not evaluated; a pass stands. Storey skipping orders storeys by the `Elevation` attribute and fails closed on an unknown elevation or a subject without exactly one storey.

`clash.rs` and `distance.rs` own pairwise policy over `ProximityServiceHandle`; `pairs.rs` holds their shared selection and broad-phase set-up. An object whose extent cannot be read is reported not evaluated, never skipped. Meeting surfaces with no penetration measurement are not evaluated, not passed. Distance maxima may conclude "none within" only when every counterpart was measured. `distance` judges `ProjectedDistanceEvidence` intervals in three modes (`nearest`, `none_closer_than`, `at_least`); a straddling, unmeasured or scope-undecided counterpart is unknown, and a verdict needs the unknowns unable to change it. Container scoping goes through `support::Traversal`; never skip a counterpart whose container is undecided.

`comparison.rs` owns the semantic session diff. Match by external identity scheme only, never by `ObjectId`. Report unidentified objects, ambiguous identities and unreadable facets; never compare an unknown as empty.
