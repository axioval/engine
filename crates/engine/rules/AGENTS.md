# `axioval-rules`

Maintained source-neutral capability policy and shared rule algorithms.

Capabilities may depend on Axioval IR and typed host-service interfaces, never concrete OpenBIM, ICDD, Axiolid, STEP, or vendor CAD types. Source interpretation belongs in adapters.

`property_rules.rs` owns property compliance policy; `selection.rs` owns fail-closed selector evaluation. Both must resolve property values and absences through `PropertyResolutionServiceHandle`. Never infer absence from a missing `Object.properties` entry, and never silently skip an object when a property selector cannot be resolved exactly. A property selector whose value has another type than it compares is not evaluated, never a non-match; `matches` and `like` match the whole value. A list value is compared only element by element under the selector's `quantifier`, never as a whole; `all` never holds vacuously. A `discipline` selector reads `SourceDisciplines`; a source without a declared discipline is `NotRecorded` with a source-only message (collapsed once per rule and source), never a non-match. A `related` selector walks its `path` with `support::Traversal`; a refused relationship answer or an undecided reached object leaves the candidate undecided, never excluded, and its `all` never holds vacuously either. `property-exists` means exact presence even when a source value is null or blank; `property-required` is the stronger non-empty contract and treats exact absence, null, and blank text as violations without converting adapter failures into findings. `property-data-type` adds the source-declared type to that contract; an unreported type is not evaluated, never a match. Dates and date-times compare only through `support::temporal_order`: dates by day, date-times as instants, and a date-time with a date only at declared `day` precision, never by a default. `property_value.rs` owns `property-value`: lexical constraints cast to the resolved value's kind. A literal or constraint that does not fit the value is not evaluated, never a pass or a violation. `xsd_pattern.rs` translates XML Schema patterns; refuse any construct it cannot map exactly rather than approximate it. Its `translate` is public as `translate_xsd_pattern` so package importers write `matches` selectors with the same meaning; keep one translation.

`support.rs` holds the shared parameter reader, exact property resolution, relationship traversal and finding construction; new capabilities use it rather than re-reading `CompiledRule.parameters` by hand. A parameter present with the wrong type is an invalid declaration, never "absent". A capability forming one scope per source takes its sources from `support::sources` (the runtime's `SessionSources`), never from the objects alone, so an empty source is judged instead of silently passing. `support::table` reads table rows and owns row matching (first, most specific, all); capabilities use `match_rows` rather than reimplementing it. It fails closed on undecided rows and reports ties for the most specific row instead of breaking them by order. `property_predicate.rs` and `property_comparison.rs` take exactly one target (none only for the presence operators); keep that check when adding target kinds. `property-comparison` compiles `like` and `matches` with the property selectors' wildcard translation in `selection.rs`, so a word means the same in both; `support.rs` owns the nearest-container climb behind `same_space`/`same_building`. The semantic capabilities (`conformance.rs`, `unique_value.rs`, `consistent_value.rs`, `counts.rs`, `object_count.rs`, `relative_count.rs`, `name_sequence.rs`, `numbering_consistency.rs`, `manual_issue.rs`) read properties, classifications and relationships only. An undecided selector or value is a not-evaluated outcome, and a count is judged only when the undecided objects cannot change the verdict. Test them against the in-memory source in `tests/common/mod.rs`. `plan_area.rs` (`area-ratio`, `plan-coverage`, `plan-area`) and `level_spacing.rs` judge measured intervals: a verdict needs the whole interval on one side of a bound, and a straddling one is not evaluated. `area-ratio` and `plan-area` measure footprints or, with `measure: facade`, facade areas; keep the two behind `plan_area::Measure` rather than a second capability. `level-spacing` measures the highest level from its contents' vertical extents and compares spaces with their level's height; only exact heights decide the prevailing one. `light_area.rs` is `area-ratio`'s `light-area` numerator mode, not a capability: its fallback (stated, table, frame allowance) moves to the next step only on an exact absence, never on an error or a wrong-typed value, and records the step in each area's evidence; keep it a mode so the ratio's judgement stays in one place. `measure: facade` with `light-area` is an invalid declaration.

`table_allocation.rs` (`table-allocation`) assigns each object to one row through `support::table::match_rows`; an object that might belong to a row it was not assigned to (tie, undecided key or selection) leaves that row's count and area not evaluated unless an excess already stands. Never break a tie or skip an undecided object. Its key-cell helpers (`key_cells`, `read_keys`, `test_keys`) are shared with `group_composition.rs`; change them in one place.

`group_composition.rs` (`group-composition`) allocates each group's members to requirement entries by a maximum bipartite matching (`Allocation`), never greedily. Report only what every maximum matching agrees on: competing short entries share one shortfall finding, competing surplus members one surplus finding. An undecided membership, member key or group key leaves the group not evaluated; an ungrouped object is found only when every group that might reach it was walked.

`keyed_limit.rs` (`keyed-limit`) selects one row of a keyed limit table per object with `match_rows` (most specific) and reuses `plan_area`'s footprint and interval judgement. A key it cannot read exactly (absent, blank, another type, reached on no object, or disagreeing across reached objects) is unknown, never a non-match; no matching row is a "no limit defined" finding, and a tie is not evaluated. Its `sill-height` quantity judges the object's bottom against each floor `floor_path` reaches separately, through `level_spacing`'s vertical-extent helpers and `plan_area::judge`; any failing floor is a finding, otherwise an undecided floor leaves the object not evaluated. Keep sill heights a quantity, not a capability, so row selection stays in one place, and keep the elevation difference widened by `difference` so it always holds the exact value. Its `clear-width` quantity takes a stated clear width, else the overall width less the rule's `width_deduction`; like `light_area.rs`, it moves on only on an exact absence. The deduction is the rule author's approximation: keep it named in the message and cited by an inexact `axioval:derived.clear-width` evidence entry, and never default it or derive a clear width without it.

`property_requirements.rs` (`property-requirements`) checks every applicable row of a requirements table per object (`match_rows`, all rows; an undecided `applies_to` leaves the object not evaluated). Findings start with their result: `missing property`, `missing value`, `forbidden property present`, `forbidden value`, `wrong value`. Set and property names are exact: the property contract cannot enumerate an object's properties (upstream openbimrs/ifc#78), so a wildcard name or a set-only row is refused once per rule, never approximated from `Object.properties` or a permissive lookup. A value condition that cannot judge a value (another kind, a unit mismatch, a straddling quotient) is not evaluated. A `requirement` row is internally a `state` row (`required` = include, `forbidden` = exclude, `optional` = include letting a missing value pass); keep one evaluation path for both. `ignore` rows are skipped before `applies_to` is evaluated and are never refused. `group_by_value` keys groups by row, category, result and the exact `support::value_key`; `category_property` goes through `support::category_prefix`, shared with `property-comparison`, and an unreadable category leaves the object not evaluated. Rounding (`decimals`) reuses `support::round_decimal` in the row's unit; without it bounds stay in canonical SI units so exact values are never rescaled.

`opening_spaces.rs` (`opening-spaces`) judges each door, window or opening by its host's declared exposure. An undeclared, null or non-boolean exposure, disagreeing hosts or no host leave the element not evaluated, never assumed internal. With the derived adjacency it reads sides only through `axioval_engine::adjacent_side`; never parse adjacency locators by hand.

`exit_separation.rs` (`exit-separation`) reaches each space's exits through `exit_path` among the `exit_selector` objects and judges pair separations against a fraction of the space's longest plan diagonal. Closest-point separation goes through `ProximityServiceHandle` (`Horizontal`), centres and farthest points through `PlanSpanServiceHandle`. An unknown flag widens the required interval to both fractions rather than guessing; an undecided exit can only add pairs, so only an `any` pass or an `all` failure stands with one. Never judge an interval by its midpoint.

`space_access.rs` (internal) reads direct access for `space_connection.rs` (`space-connection`) and `space_distance.rs` (`space-distance`): each door or opening reaches its spaces through `access_path`; with the derived adjacency the spaces must lie on opposite faces (read with `adjacent_side`) and a face entering no space is the outside, which a stated relationship can never show. A link through an element of undecided type, or any element whose spaces are unreadable, is unknown, never "no"; keep both capabilities on this one reader. `space-distance` bounds the nearest distance from above by surely qualifying destinations and from below by every possible one (an unmeasured one counting as zero), so a refused route decides only what it cannot change; a blocked route is no destination. Walking starts at an exact footprint centroid inside the footprint (`PlanSpanServiceHandle::measure_centre`) on the space's exact floor; never substitute another point for a centroid outside it. Pairs are routed one by one until a many-target search exists (axiolid/kernel#186).

`counterpart_coverage.rs` (`counterpart-coverage`) grades each element's uncovered share of footprint and height against its counterparts' union, grown by the tolerances, into severity bands. Near counterparts come from the plan broad phase; each is sorted by whether its grown footprint surely or possibly covers part of the element through the uncovered area alone. The least cover (selected, surely overlapping) gives the upper bound, the most cover (with undecided and possible ones) the lower; an unreadable counterpart drops the lower bound to zero, so only a pass stands. Never filter counterparts by axis until a minimum-area rectangle exists upstream.

`accessible_route.rs` (`accessible-route`) takes one walkability snapshot for its mobility profile and judges each passage through `WalkabilitySnapshot::route_between_admitting`; never walk the passage graph here. Portal and connector minimum widths are the rule's admission, stated widths come only from `clear_width_property` as a length (anything else is undecided, never absent) and are sent with the request so the geometry can admit the body through a door. A forbidden stair is `Refused`; an undecided selection is `Undecided`, never excluded; a region of an object that is neither route space, portal, start nor destination of the pair is `Refused`. A finding needs every start proven cut off and relates `blocking_passages`' elements; an undecided obstacle leaves every destination not evaluated. Passing spaces wait on the placement search.

`slab_stack.rs` (`slab-stack-spacing`) pairs slabs by plan-overlap ratio and judges vertical-extent intervals between consecutive slabs, reusing `level_spacing::prevailing` for consistency. An undecided overlap ratio, an unorderable pair of tops, an undecided-selection object that may stack, or any unmeasurable extent is not evaluated; enclosing proximity boxes may only skip overlaps that are provably zero.

`free_floor_circle.rs` and `free_floor_rectangle.rs` own exact grounded vertical-shape profiles. They must request whole-base support and all project objects as candidate obstacles. Missing services, backend failures, and invalid/incomplete proofs emit typed not-evaluated outcomes; they never produce a pass or compliance finding. The rectangle must state its orientation explicitly; never default it to the world axes.

`external_wall_validation.rs` resolves each derivation's bounding objects (`bounding_selector`, or the members of `gross_area_group_selector` along `gross_area_group_path`) and sends them in the `EnvelopeMembershipRequest`; never let the host choose them. An undecided or empty bounding set leaves that derivation not evaluated; each derivation in `derivations` is reported on its own.

`slab_contact.rs` resolves its `counterparts` selector and sends the candidates in every `ContactRequest`; the adapter measures only those. A shortfall with undecided counterparts is not evaluated; a pass stands. Storey skipping orders storeys by the `Elevation` attribute and fails closed on an unknown elevation or a subject without exactly one storey.

`clash.rs` and `distance.rs` own pairwise policy over `ProximityServiceHandle`; `pairs.rs` holds their shared selection and broad-phase set-up. An object whose extent cannot be read is reported not evaluated, never skipped. Meeting surfaces with no penetration measurement are not evaluated, not passed. `clash` puts each pair in one class (duplicate, containment, intersection, then clearance); a switched-off class hides its pairs rather than reclassifying them. Hausdorff distances and overlap extents are judged as intervals: a straddling one decides only when both readings agree, and an unmeasured one is undecided. Exclusions (`exclude_paths`, `exclude_same_layer`) are decided before measuring; an undecided exclusion leaves a would-be finding not evaluated and never hides it. The presentation layer is requested by its engine name, never through package concept binding. `clash_matrix.rs` (`clash-matrix`) picks one cell per pair with `match_rows` (most specific: keyed categories first, then literals) and judges it with `clash.rs`'s shared `Profile`, `Exclusions`, `measure`, `unless_excluded` and `Recorder`; never copy the pair judgement into it. A tie or an unreadable category (discipline via `selection::discipline_of`, keys via `table_allocation::read_keys`, selector cells) leaves the pair not evaluated, never judged by another cell; an unmatched pair is never measured. Same-system exclusion needs a declared `system_path`: never default it to a source's relationship name. Distance maxima may conclude "none within" only when every counterpart was measured. `distance` judges `ProjectedDistanceEvidence` intervals in three modes (`nearest`, `none_closer_than`, `at_least`); a straddling, unmeasured or scope-undecided counterpart is unknown, and a verdict needs the unknowns unable to change it. Container scoping goes through `support::Traversal`; never skip a counterpart whose container is undecided.

`body_extent.rs` (`body-extent`) measures a body along its own placement axis (object frame, then directional extent) and judges the interval with `plan_area::judge`; the rule states the axis, never a default. A target property that is not a length is not evaluated; an absent one is a finding. `triangle_count.rs` (`triangle-count`) judges the host's mesh count and says so on a tessellation. `same_container.rs` (`same-container`) compares nearest containers (`support::Traversal::nearest_containers`) of an object and its counterparts; an undecided container selection or counterpart is not evaluated, never skipped.

`stair_geometry.rs` (`stair-geometry`, `ramp-geometry`) judges the stair-geometry service's derived intervals: each declared check is its own finding or not-evaluated outcome, and a straddling interval never decides. Headroom obstacles are the rule's `headroom_obstacles` selection, sent in the request; an undecided obstacle can only lower headroom, so a shortfall stands and a pass is not evaluated. Keep both capabilities on one module so the headroom judgement stays in one place.

`component_clearance.rs` (`component-clearance`) places a fixed box or cylinder on a stated side of each component's placement frame. The front is the rule's `front_axis` or the source's `ObjectFront::Stated`, never inferred. The volume starts at the component's directional extent, and every measured position is an interval: clear needs the union of all positions clear, obstructed needs their common part obstructed, anything else is not evaluated. Undecided obstacles are sent as candidates, so a clear volume stands, and an obstruction by them alone is re-asked without them. Protrusion shrinks the checked volume on every plan side; `within_space` uses `assess_containment` on the declared volume. Sliding (floating) volumes wait for the placement search (#18).

`comparison.rs` owns the session diff behind `axioval compare`. It is a host entry point, not a capability: it needs two sessions. Match by external identity scheme only, never by `ObjectId`. Report unidentified objects, ambiguous identities and unreadable facets; never compare an unknown as empty. The spatial facets (placement, geometry, coordinate systems) are opt-in and read only typed services (`ObjectFrameServiceHandle`, `ProximityServiceHandle`, `CoordinateSystemServiceHandle`). Every measure is an interval judged by `Outcome::measured`: changed only when the whole interval exceeds the tolerance, unchanged only when none of it does, otherwise undetermined; never round a straddling interval. Geometry widens the bounds shift by both chord deviations; bodiless (`ProximityError::NoBody`) on both sides is agreement, `Unavailable` is unresolved. Do not implement a mesh difference here: a certified Hausdorff distance is axiolid/kernel#148. The report's rule ids (`RULE.added`, `RULE.<facet>`, `RULE.identity`) are a CLI contract.
