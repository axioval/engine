# `axioval-rules`

Maintained source-neutral capability policy and shared rule algorithms.

Capabilities may depend on Axioval IR and typed host-service interfaces, never concrete OpenBIM, ICDD, Axiolid, STEP, or vendor CAD types. Source interpretation belongs in adapters.

`property_rules.rs` owns property compliance policy; `selection.rs` owns fail-closed selector evaluation. Both must resolve property values and absences through `PropertyResolutionServiceHandle`. Never infer absence from a missing `Object.properties` entry, and never silently skip an object when a property selector cannot be resolved exactly. A property selector whose value has another type than it compares is not evaluated, never a non-match; `matches` and `like` match the whole value. A list, bounded or table value is compared only by its stated values (`PropertyValue::stated_values`) under the selector's `quantifier`, never as a whole; `all` never holds vacuously. A `discipline` selector reads `SourceDisciplines`; a source without a declared discipline is `NotRecorded` with a source-only message (collapsed once per rule and source), never a non-match. A match on a mapped discipline cites the map rule and value (`DisciplineOrigin::locator`) as inexact evidence. A `source` selector reads `SourceMetadataIndex` the same way: an unread field is `NotRecorded` once per source, a field read and empty is an absent value (no operator matches), several values need `quantifier`; it compares through the same `Test` as property selectors. `isEmpty` and `isNotEmpty` mean `property-requirements`' `empty` and `not-empty` (`support::undefined`), judge the value whole and are false for an absent property. A `classification` selector's `codePattern` is an XML Schema pattern compiled by `xsd_pattern::compile` and matched as `classification` (the capability) matches codes; without `code` or `codePattern` it tests the system alone. A `related` selector walks its `path` with `support::Traversal`; a refused relationship answer or an undecided reached object leaves the candidate undecided, never excluded, and its `all` never holds vacuously either. `property-exists` means exact presence even when a source value is null or blank; `property-required` is the stronger non-empty contract and treats exact absence, null, and blank text as violations without converting adapter failures into findings. `property-data-type` adds the source-declared type to that contract; an unreported type is not evaluated, never a match. Dates and date-times compare only through `support::temporal_order`: dates by day, date-times as instants, and a date-time with a date only at declared `day` precision, never by a default. `property_value.rs` owns `property-value`: lexical constraints cast to the resolved value's kind. A literal or constraint that does not fit the value is not evaluated, never a pass or a violation. A composite value needs `quantifier`; under `all` a bounded value open on a bounded side fails, since a range holds every value between its ends (keep this in step with `property-requirements`). A quantity is compared only under `si_units`, never as a bare number by default. Name patterns (`propertyPattern` selectors, `property_pattern` of `property-value`, the pattern columns of `property-requirements`) are XML Schema patterns compiled by `selection::xsd_name_pattern` and matched against source names through `bound_enumeration_request`, which binds only exact names through the package vocabulary; a pattern is never a concept. A `propertyPattern` selector with no match is no match, even under `matched: all`. `xsd_pattern.rs` translates XML Schema patterns; refuse any construct it cannot map exactly rather than approximate it. Its `translate` is public as `translate_xsd_pattern` so package importers write `matches` selectors with the same meaning; keep one translation.

`support.rs` holds the shared parameter reader, exact property resolution, relationship traversal and finding construction; new capabilities use it rather than re-reading `CompiledRule.parameters` by hand. A parameter present with the wrong type is an invalid declaration, never "absent". A capability forming one scope per source takes its sources from `support::sources` (the runtime's `SessionSources`), never from the objects alone, so an empty source is judged instead of silently passing. `support::table` reads table rows and owns row matching (first, most specific, all); capabilities use `match_rows` rather than reimplementing it. It fails closed on undecided rows and reports ties for the most specific row instead of breaking them by order. `property_predicate.rs` and `property_comparison.rs` take exactly one target (none only for the presence operators); keep that check when adding target kinds. `property-comparison` compiles `like` and `matches` with the property selectors' wildcard translation in `selection.rs`, so a word means the same in both; `support.rs` owns the nearest-container climb behind `same_space`/`same_building`. The semantic capabilities (`conformance.rs`, `unique_value.rs`, `consistent_value.rs`, `counts.rs`, `object_count.rs`, `relative_count.rs`, `name_sequence.rs`, `numbering_consistency.rs`, `manual_issue.rs`) read properties, classifications and relationships only. `object-count`'s `disciplines` reads `SourceDisciplines`: a source of another discipline is not counted, one declaring none is never skipped (not evaluated per source, undecided across sources). An undecided selector or value is a not-evaluated outcome, and a count is judged only when the undecided objects cannot change the verdict. Test them against the in-memory source in `tests/common/mod.rs`. `plan_area.rs` (`area-ratio`, `plan-coverage`, `plan-area`) and `level_spacing.rs` judge measured intervals: a verdict needs the whole interval on one side of a bound, and a straddling one is not evaluated. `area-ratio` and `plan-area` measure footprints or, with `measure: facade`, facade areas; keep the two behind `plan_area::Measure` rather than a second capability. `level-spacing` measures the highest level from its contents' vertical extents and compares spaces with their level's height; only exact heights decide the prevailing one. `light_area.rs` is `area-ratio`'s `light-area` numerator mode, not a capability: its fallback (stated, table, frame allowance) moves to the next step only on an exact absence, never on an error or a wrong-typed value, and records the step in each area's evidence; keep it a mode so the ratio's judgement stays in one place. `measure: facade` with `light-area` is an invalid declaration. `level-spacing` (`levels`, `spaces`), `plan-area` (`areas`) and `area-ratio` (`ratios`) report every measured value as a report table, passing or not, without a parameter (a new parameter would break every definition's signature); keep the table names and column ids stable, they are a report contract.

`classification_requirement.rs` (`classification`) states what a `classification` selector cannot: a system alone, systems and codes as XML Schema patterns, optional and prohibited. It reads the same `ClassificationServiceHandle` and decides as the selector does: one assignment meets the system and the code together, codes match the whole ancestor chain, and an assignment without a stated system is undecided when it could change the verdict, never a match or a non-match. Keep the two in step.

`table_allocation.rs` (`table-allocation`) assigns each object to one row through `support::table::match_rows`; an object that might belong to a row it was not assigned to (tie, undecided key or selection) leaves that row's count and area not evaluated unless an excess already stands. Never break a tie or skip an undecided object. Its key-cell helpers (`key_cells`, `read_keys`, `test_keys`) are shared with `group_composition.rs`; change them in one place.

`group_composition.rs` (`group-composition`) allocates each group's members to requirement entries by a maximum bipartite matching (`Allocation`), never greedily. Report only what every maximum matching agrees on: competing short entries share one shortfall finding, competing surplus members one surplus finding. An undecided membership, member key or group key leaves the group not evaluated; an ungrouped object is found only when every group that might reach it was walked.

`keyed_limit.rs` (`keyed-limit`) selects one row of a keyed limit table per object with `match_rows` (most specific) and reuses `plan_area`'s footprint and interval judgement. A key it cannot read exactly (absent, blank, another type, reached on no object, or disagreeing across reached objects) is unknown, never a non-match; no matching row is a "no limit defined" finding, and a tie is not evaluated. Its `sill-height` quantity judges the object's bottom against each floor `floor_path` reaches separately, through `level_spacing`'s vertical-extent helpers and `plan_area::judge`; any failing floor is a finding, otherwise an undecided floor leaves the object not evaluated. Keep sill heights a quantity, not a capability, so row selection stays in one place, and keep the elevation difference widened by `difference` so it always holds the exact value. Its `clear-width` quantity takes a stated clear width, then with `clear_width_from_leaves` the overall width less both linings and every hinged leaf's depth from the door's leaves (moving on on `NotStated`, a missing thickness or a leaf that does not swing), else the overall width less the rule's `width_deduction`; like `light_area.rs`, it moves on only on an exact absence. The deduction is the rule author's approximation: keep it named in the message and cited by an inexact `axioval:derived.clear-width` evidence entry, and never default it or derive a clear width without it.

`property_requirements.rs` (`property-requirements`) checks every applicable row of a requirements table per object (`match_rows`, all rows; an undecided `applies_to` leaves the object not evaluated). Findings start with their result: `missing property`, `missing value`, `forbidden property present`, `forbidden value`, `wrong value`. Exact names resolve through `support::resolve`; a wildcard cell, a `property_set_pattern`/`property_pattern` cell (XML Schema) or a set-only row goes through `selection::enumerate` and `check_matched_row`: an included statement holds for every match and needs one (in every named set, through `selection::sets_without_match`, shared with `property-value`), an excluded one for none, and a refused enumeration leaves the object not evaluated, never approximated from `Object.properties` or a permissive lookup. A set holds a property or is absent; a set-only row states only `defined`/`undefined`. `missing_set` refines a `missing property` to `missing property set` only on an exact empty enumeration of the set; a refusal keeps the plain result, which is true either way. A value condition that cannot judge a value (another kind, a unit mismatch, a straddling quotient) is not evaluated. A `requirement` row is internally a `state` row (`required` = include, `forbidden` = exclude, `optional` = include letting a missing value pass); keep one evaluation path for both. `ignore` rows are skipped before `applies_to` is evaluated and are never refused. `group_by_value` keys groups by row, category, result and the exact `support::value_key`; `category_property` goes through `support::category_prefix`, shared with `property-comparison`, and an unreadable category leaves the object not evaluated. Rounding (`decimals`) reuses `support::round_decimal` in the row's unit; without it bounds stay in canonical SI units so exact values are never rescaled.

`opening_spaces.rs` (`opening-spaces`) judges each door, window or opening by its host's declared exposure. An undeclared, null or non-boolean exposure, disagreeing hosts or no host leave the element not evaluated, never assumed internal. With the derived adjacency it reads sides only through `axioval_engine::adjacent_side`; never parse adjacency locators by hand.

`exit_separation.rs` (`exit-separation`) reaches each space's exits through `exit_path` among the `exit_selector` objects and judges pair separations against a fraction of the space's longest plan diagonal. Closest-point separation goes through `ProximityServiceHandle` (`Horizontal`), centres and farthest points through `PlanSpanServiceHandle`. An unknown flag widens the required interval to both fractions rather than guessing. `flag_sources` (or `flag` with `flag_path`, one source) is read in order and moves to the next source, then to `flag_default`, only on an exact absence (a path reaching nothing, or every reached object lacking the property); a refused read, a null, a non-boolean, a disagreement or a partial statement stops at unknown, never reading past it. An undecided exit can only add pairs, so only an `any` pass or an `all` failure stands with one. Never judge an interval by its midpoint.

`corridor_end_openings.rs` (`corridor-end-openings`) judges each opening `opening_path` reaches from a selected corridor against every end wall `PlanSpanServiceHandle::measure_corridor_ends` returns: in the wall when the whole gap lies within `wall_depth` and the whole facing beyond `facing`, out when either lies wholly on the other side. An undecided end wall or straddling interval leaves an opening not found elsewhere not evaluated, never passed; a selector-undecided opening is not evaluated only where it would be found. Findings are on the opening and relate the corridor. Never guess an undecided wall from the end's point or the space's shape.

`space_access.rs` (internal) reads direct access for `space_connection.rs` (`space-connection`), `space_distance.rs` (`space-distance`) and `effective_coverage.rs` (`effective-coverage`, `connections`): each door or opening reaches its spaces through `access_path`; with the derived adjacency the spaces must lie on opposite faces (read with `adjacent_side`) and a face entering no space is the outside, which a stated relationship can never show. A link through an element of undecided type, or any element whose spaces are unreadable, is unknown, never "no"; keep every capability on this one reader (`local-circulation` reads a space's entrances with `AccessIndex::entrances`). `space-distance` bounds the nearest distance from above by surely qualifying destinations and from below by every possible one (an unmeasured one counting as zero), so a refused route decides only what it cannot change; a blocked route is no destination. Walking starts at an exact footprint centroid inside the footprint (`space_distance::representative_point`, shared with `escape-route`) on the space's exact floor; never substitute another point for a centroid outside it. Walking takes two `nearest_target` queries, the sure destinations for the upper bound and every possible one for the lower; never go back to routing pairs one by one. `closest` measures pair by pair like `straight`, through `ProximityServiceHandle::measure_distance` (`Minimum3d`), never a plan distance: bodies stacked on two storeys are not zero apart.

`escape_route.rs` (`escape-route`) picks the first `uses` row per space (`match_rows`, first) and reaches exits as `exit-separation` does (its `Candidates`). Travel is a point's walking line to the exits' representative points: `farthest_point` over the space for `farthest-point`, `nearest_target` from each door for `door`; the sure exits bound it from above, every possible exit from below, and an exit without a point drops the lower bound to zero. With doors, a finding needs one sure door too far, a pass every possible door. The occupant load rounds the footprint interval up at both ends and takes every `widths` row between them; a stated clear width decides both ways, a footprint's longest plan diagonal only a failure. `sections` factors (at least one) bracket the multiplied travel between the plain walk's lower bound and an upper bound: the plain upper bound times the largest factor of a section the walk may cross (only a section whose horizontal distance from the start surely exceeds that upper bound, or a `shared_by` section fewer checked spaces (sure, undecided or unreadable) could reach along `section_path`, is left out), or, from a door, where tighter, the answer's own walk traced over the sections (`walked_cost`: the plain upper bound plus each section's traced upper length times its factor less one, an untraced section counting the whole walk). The traced walk bounds only from above: never lower the lower bound from it, and never trace from the farthest point, whose witness is a point, not a walk. Passages (`passage_selector`, reached along `passage_path` or the space itself) carry the summed loads of every checked space reaching them, and are judged per passage in `judge_passages`, merged into the passage's own outcome when it is a checked space; a possibly reaching space with an unknown load leaves the passage not evaluated. With `walked_passages` (`walked`, `door_passages`) a space surely relies on a passage only when from every door the walk to every possible exit avoiding it (`with_avoided`) is longer than the plain walk's upper bound to the sure exits or unreachable, with every exit placed and one sure; the witness walk's trace only picks the candidates, never proves reliance, because shortest walks may tie. It may rely on every passage not ruled off by the door-to-passage-to-exit plan distances exceeding that upper bound; anything unwalkable may rely on every passage. Sure loads count in `least`, possible ones only in `most`, and a passage no space surely relies on is never a finding. A stated `passage_width_property` decides both ways, the shorter side of a uniquely oriented least-area rectangle only a failure. `exit_door_direction` judges each exit door with `door_swing::relation` against the checked space: `Into` a sure exit is a finding, `Away` and `BothWays` pass, an exit that is not a door is skipped, and a sure door without a hinged leaf, unknown leaves or `Apart` leave the space not evaluated; never read `Apart` as opening away.

`shelf_capacity.rs` (`shelf-capacity`) reads each space's doors through `space_access`'s `AccessIndex::reaching` and sends them in the `LinearQuantityRequest`; an unreadable or undecided element that may reach the space leaves it not evaluated, never measured without its clearance. "Space too low for the shelving" is its own finding, from the evidence's clear height against the top elevation. `recess_width.rs` (`recess-width`) judges each recess from `PlanSpanServiceHandle::measure_recesses` by the first row (`match_rows`) whose depth range holds it; `light_well.rs` (`light-well`) judges a well's members (`member_path`) for vertical gaps, an empty shared section (`measure_section`), and the section's area and width against the first row its height selects; a section the service refuses (a tessellated member, or a tied least-area rectangle whose sides are unknown) leaves the well not evaluated, never judged from another rectangle. Envelope adjacency is a `distance` rule over walls declared external; do not add a capability for it.

`counterpart_coverage.rs` (`counterpart-coverage`) grades each element's uncovered share of footprint and height against its counterparts' union, grown by the tolerances, into severity bands. Near counterparts come from the plan broad phase; each is sorted by whether its grown footprint surely or possibly covers part of the element through the uncovered area alone. The least cover (selected, surely overlapping) gives the upper bound, the most cover (with undecided and possible ones) the lower; an unreadable counterpart drops the lower bound to zero, so only a pass stands. With `axis_tolerance`, a counterpart surely at another angle is left out and one whose angle or axes are undecided (`orientation.rs`) is a possible cover only, never a sure one.

`orientation.rs` (internal) reads least-area rectangles through `PlanSpanServiceHandle::measure_rectangle` and judges long-axis angles three-valued (`Tri`, `Alignment`); only a unique orientation with one surely longer side has a long axis, and an angle tolerance lies in `[0, 45)` degrees so the alignments never overlap. `parking_bay.rs` (`parking-bay`) judges a bay's width and length on its rectangle (`width_and_length`, never a bounding box), its height on its vertical extent, its angle to aisles within `aisle_reach`, and obstacles within `obstruction_reach` per end and side from directional extents along the bay's axes widened by the axis error; an undecided or unplaceable obstacle may obstruct any edge. `side_zone_length` narrows the span a side obstruction must overlap to the central stretch (`central`), never the side line. With `applies_when` `filter` the orientation and obstruction states are sets of possible states (`Bay::oriented`, `Count::possible`), never findings: a size bound applies when every possible state is allowed (`within`), is skipped when none is, and otherwise keeps its pass and turns its failure into not evaluated; an obstacle within the bay stays a finding. Orientation is read against sure aisles, or with `neighbour_reach` against the rule's own bays parallel to the bay (`beside`: the direction to a neighbour's centre, judged as a row aisle would be); none or disagreeing ones are `unclear`, and an uncertain one only widens the set. The broad phase names a pair of two bays once, so `Nearby` records it both ways. `wall_spacing.rs` (`wall-spacing`) pairs members reached along `member_path` that are parallel and face each other along the first one's long axis; the minimum judges each pair's `horizontal` distance, the maximum measures each footprint's area outside the pairs' `PlanBand`s (least from sure bands, most from possible ones, zero with any unknown member).

`accessible_route.rs` (`accessible-route`) takes one walkability snapshot for its mobility profile and judges each passage through `WalkabilitySnapshot::route_between_admitting`; never walk the passage graph here. Portal and connector minimum widths are the rule's admission, stated widths come only from `clear_width_property` as a length (anything else is undecided, never absent) and are sent with the request so the geometry can admit the body through a door. A forbidden stair is `Refused`; an undecided selection is `Undecided`, never excluded; a region of an object that is neither route space, portal, start nor destination of the pair is `Refused`. A finding needs every start proven cut off and relates `blocking_passages`' elements; an undecided obstacle, or an undecided or unreadable `subtract_door_swings` door, leaves every destination not evaluated. Swept doors go into the walkability request and the passing-space searches. `passing_spaces.rs` (internal) judges passing spaces on each proven route: the route is the metric-routing polyline between `space_distance::representative_point`s (keep one representative point), cut into tiles no longer than half the spacing less the slop, each searched per segment piece with a frame-offset placement domain anchored on the segment. Only a witness in every interior tile passes and only a run of tiles proven empty longer than the spacing is a finding; never interpolate between tiles or treat a refused tile as empty. A metric route crossing anything but route spaces and decided portals is not evaluated. `passing_spaces::judge_path` judges any polyline in one space the same way; keep the tile logic in `Search::along` so both callers share it.

`local_circulation.rs` (`local-circulation`) judges one `CirculationMap` per selected space. A component is reached only through a piece shared with a surely selected entrance and cut off only when its possible pieces miss every entrance's, sure or possible (an element whose spaces cannot be read is a possible entrance); `link` mode compares components pairwise the same way. Path ends are the skeleton ends of pieces a sure entrance reaches; an end's heading is taken over at least its half width, never from its nearest neighbour, which may lie a rounding away. Exemptions (`short_end_metres`, `narrow_end_metres`) are three-valued and the branch length carries two sample spacings of slack each way; an undecided exemption never turns a proof of no free area into a finding. Passing spaces are traced along the skeleton, simplified to a quarter of the width, and judged by `passing_spaces::judge_path`. `subtract_door_swings` doors' sectors go into the circulation request, the end-area searches and the passing spaces (`door_swing::Swings`, never guessed from a door's body); an undecided or unreadable swing, like an undecided obstacle, leaves every space not evaluated.

`door_swing_direction.rs` (`door-swing`) judges each door's reached spaces with `door_swing::relation`: containment probes on both sides of each hinged leaf (halfway through the sweep, three quarters of the width out). A swing-side probe inside is `Into` (`BothWays` for a double-acting leaf), a back probe inside with the swing side outside `Away`, both outside `Apart`, which decides nothing. `swing_into` fails only when every picked space is surely `Away`; never read `Apart` as away. A door without a hinged leaf is not evaluated. `escape-route` shares `relation`; keep one probe rule.

`slab_stack.rs` (`slab-stack-spacing`) pairs slabs by plan-overlap ratio and judges vertical-extent intervals between consecutive slabs, reusing `level_spacing::prevailing` for consistency. An undecided overlap ratio, an unorderable pair of tops, an undecided-selection object that may stack, or any unmeasurable extent is not evaluated; enclosing proximity boxes may only skip overlaps that are provably zero.

`free_floor_circle.rs` and `free_floor_rectangle.rs` own exact grounded vertical-shape profiles; `free_floor.rs` holds their shared options and judgement, so change both through it. Without `obstacles` every other project object is a candidate obstacle; an undecided obstacle is sent as a candidate, and a no-placement proof stands only when it holds again without the undecided ones. The band (`band_from_metres`, `band_to_metres`) goes into the request; never filter obstacles by height here. Spaces `merge_path` reaches are merged scopes, never obstacles; without them the request requires whole-base support on the space, with them it is unconstrained (no single support holds the base). `subtract_door_swings` swings follow the obstacle rule: undecided ones are sent first and a proof must hold without them; a door whose leaves are unknown turns a witness into not evaluated, never a proof. Missing services, backend failures, and invalid/incomplete proofs emit typed not-evaluated outcomes; they never produce a pass or compliance finding. The rectangle must state its orientation explicitly; never default it to the world axes. No free corridor option: connectivity of an eroded region is not decided soundly yet.

`external_wall_validation.rs` resolves each derivation's bounding objects (`bounding_selector`, or the members of `gross_area_group_selector` along `gross_area_group_path`) and sends them in the `EnvelopeMembershipRequest`; never let the host choose them. An undecided or empty bounding set leaves that derivation not evaluated; each derivation in `derivations` is reported on its own.

`slab_contact.rs` resolves its `counterparts` selector and sends the candidates in every `ContactRequest`; the adapter measures only those. A shortfall with undecided counterparts is not evaluated; a pass stands. Storey skipping orders storeys by the `Elevation` attribute and fails closed on an unknown elevation or a subject without exactly one storey.

`clash.rs` and `distance.rs` own pairwise policy over `ProximityServiceHandle`; `pairs.rs` holds their shared selection and broad-phase set-up. An object whose extent cannot be read is reported not evaluated, never skipped. Meeting surfaces with no penetration measurement are not evaluated, not passed. `clash` puts each pair in one class (duplicate, containment, intersection, then clearance); a switched-off class hides its pairs rather than reclassifying them. Hausdorff distances, overlap extents and the shared volume (`volume_tolerance_cubic_metres`) are judged as intervals: a straddling one decides only when both readings agree, and an unmeasured one is undecided. Exclusions (`exclude_paths`, `exclude_same_layer`) are decided before measuring; an undecided exclusion leaves a would-be finding not evaluated and never hides it. `exclude_target_property` compares the values of reached targets only, never the members themselves, and needs an exclusion path; `exclude_same_layer` holds only within one source, since layer names are per model. The presentation layer is requested by its engine name, never through package concept binding. `clash_matrix.rs` (`clash-matrix`) picks one cell per pair with `match_rows` (most specific: keyed categories first, then literals) and judges it with `clash.rs`'s shared `Profile`, `Exclusions`, `measure`, `unless_excluded` and `Recorder`; never copy the pair judgement into it. A tie or an unreadable category (discipline via `selection::discipline_of`, keys via `table_allocation::read_keys`, selector cells) leaves the pair not evaluated, never judged by another cell; an unmatched pair is never measured. Same-system exclusion needs a declared `system_path`: never default it to a source's relationship name. `clash_groups.rs` (internal) groups reported pairs for both (`group_by`, `per_storey`): `Recorder` hands every finding to `Groups`, which keys it (cell, class, types, rounded extents, storeys) and emits one finding per group on its most involved object at its most severe severity. Grouping never decides a finding: a pair whose key cannot be read is reported alone with the reason, never merged, and a group never spans two matrix cells. `clash_severity.rs` (internal) owns clash-specific severities (`severity_by_class`, `grade_by`/`severity_grades` on intersections) and the duplicate comparison (`duplicate_quantities`); keep them in the clash capabilities, apart from any rule-wide severity mechanism. Order: an intersection's grade, a matrix cell's severity, the class's, the rule's. A straddling or unmeasured measure takes the most severe grade it may reach, never a milder one; an unreadable quantity is unknown, never the same. Distance maxima may conclude "none within" only when every counterpart was measured. `distance` judges `ProjectedDistanceEvidence` intervals in three modes (`nearest`, `none_closer_than`, `at_least`); an unreadable quantity is unknown, never the same. `clash_cases.rs` (internal) owns `tolerance_cases`: the extent of an intersection along the first or second element's placement axes (`ObjectFrameServiceHandle`), measured by `measure_overlap_along` once per pair and only when a case can change the outcome (`clash::judge_with_cases`). A case excuses only on sure filters and a whole extent within the tolerance; an undecided filter, frame or extent leaves the pair open, never excused or reported. Never measure a case along world axes. Distance maxima may conclude "none within" only when every counterpart was measured. `distance` judges `ProjectedDistanceEvidence` intervals in three modes (`nearest`, `none_closer_than`, `at_least`); a straddling, unmeasured or scope-undecided counterpart is unknown, and a verdict needs the unknowns unable to change it. Container scoping goes through `support::Traversal`; never skip a counterpart whose container is undecided. `vertical_direction` is not `direction` (a traversal parameter) and applies only to `vertical`; anything else is an invalid declaration. `subject_extent`/`counterpart_extent` `leaf_swing` (the older `door_swing` stays accepted) measure a side by its swing footprint (`door_swing::Footprint`: side-hinged sectors of doors and window casements, and a tilting window panel's exact plan rectangle) in `horizontal` only: against a body through `measure_region_distance` (lower bound from the circumscribed regions, upper from the inscribed), swing to swing with `ConvexPlanRegion::separation`; the broad phase is the plan box gap. A door or window whose leaves neither swing nor tilt has no distance; unreadable leaves are unknown, never empty. `door_swing.rs` (internal) is the one reader of door and window leaves and polygoniser of swings for every capability; keep `SEGMENTS` there. Its `Swings::select` reads a `subtract_door_swings` selection into sure, undecided and unknown `SweptDoor`s; every capability subtracting swings goes through it.; keep `SEGMENTS` there.

`containment.rs` (`containment`) decides containment by the certified shared volume's ratio to the smaller body (`IntersectionVolume::ratio_of_smaller`), judged on the interval; it measures each broad-phase pair once through `clash::measure` and reads it from whichever end is inner. `combine_adjacent` bounds a combination's shared volume by the sum of the shares less the members' mutual overlaps, never below the largest share, and reads an undecided adjacency both ways. Cover bands judge `FaceDistanceEvidence` (inside the signed distance, outside its negation) only against outer elements the inner one surely lies in alone: a combination's faces are not one body's, so its cover is not evaluated, never measured member by member. Counts take the undecided and unmeasurable inner elements as possible, and an orphan needs every containment decided and every outer element measured.

`space_boundary_coverage.rs` (`space-boundary-coverage`) judges `BoundaryCoverageServiceHandle` answers per selected space: covered share, uncovered area and overlap area, each its own finding or not-evaluated outcome through `plan_area::judge`. A boundary off the body's surface is always a finding relating its element, never dropped; overlap findings relate only the elements of pairs that surely overlap.

`body_extent.rs` (`body-extent`) measures a body along its own placement axis (object frame, then directional extent) and judges the interval with `plan_area::judge`; the rule states the axis, never a default. A target property that is not a length is not evaluated; an absent one is a finding. `triangle_count.rs` (`triangle-count`) judges the host's mesh count and says so on a tessellation. `same_container.rs` (`same-container`) compares nearest containers (`support::Traversal::nearest_containers`) of an object and its counterparts; an undecided container selection or counterpart is not evaluated, never skipped. `levels.rs` (internal) matches containers across sources for `container_relationship` `axioval:derived.same-level` by the rule's `level_property`, for `property-comparison` (`overlap`) and `same-container` (`equivalent`): a container is its own level, containers of one source never share one, and an unstated level leaves the pair undecided, never another level. Keep both capabilities on it.

`stair_geometry.rs` (`stair-geometry`, `ramp-geometry`) judges the stair-geometry service's derived intervals: each declared check is its own finding or not-evaluated outcome, and a straddling interval never decides. `walking_line_offset` goes into the `TreadFlightRequest`; a winder angle or riser closure the service did not measure leaves its check not evaluated. Headroom obstacles are the rule's `headroom_obstacles` selection, sent in the request; an undecided obstacle can only lower headroom, so a shortfall stands and a pass is not evaluated. Spaces below (`headroom_below_spaces`) follow the same `Clearance` judgement. Landing candidates (`landing_objects`) are sent decided only: an undecided one might carry the landing, so a missing landing or a shortfall with one is not evaluated, while a pass stands. `width_minimum`/`width_maximum` judge the flight's width, which needs every tread's sides: a winder has none, so a flight with winders is not evaluated, never judged on its straight treads alone. `landing_at_least_walking_width` compares against the flight's or run's width interval; an unmeasured width or a landing that is no rectangle is not evaluated, never approximated. A turning flight's landing is compared with the width of the tread meeting it (its winders have none); a side whose first or last piece lies along another part than the end's does not reach that end, a finding. A service refusing a turning flight's landings or handrails leaves those checks not evaluated. Handrails (`stair_geometry/handrails.rs`) are the rule's `handrail_objects` selection, sent with both reaches and the extension; an undecided rail may supply a missing side or be too low, so a missing side and a pass are not evaluated while a failing rail stands. The rails along a side are one handrail in pieces (`HandrailEvidence::side_rail`): its extension comes from its first and last piece, its continuity from the gaps between consecutive ones (`handrail_gap_maximum`), heights from every piece; unordered pieces leave the side's extension and gaps not evaluated, an undecided rail may continue a short extension or bridge a gap (not evaluated), and a rail reaching over the middle may be a piece, so its short extension is not evaluated. Never order pieces here. A rail's top must stay level over the extension within `LEVEL_RISE` (a micrometre, the rounding of placements); never widen that into a slope tolerance. A ramp's end spaces and the landing doors of ramps and flights (`stair_geometry/ramp_ends.rs`, asked through `LandingDoors` at every measured landing) place a box and ask `FreeSpaceServiceHandle::assess_clearance`, the ramp or flight never an obstacle; a door check measures the landing's rectangle, never a box of its own, at the run's end elevation or a flight's `landing_level` (its base at the bottom, its top or last tread at the top). `landing_door_swing` reads each selected door's `door_swing::Footprint` and vertical extent once per rule and judges them against that rectangle in plan (sure overlap: an inscribed sector part meets the sure rectangle; clear: every circumscribed part is apart from the possible one) and against the column by height; a door surely beside the column in height is skipped even with unknown leaves. A stair near a ramp is a `distance` rule, not a parameter here. Keep both capabilities on one module so the headroom, width, landing and handrail judgements stay in one place.

`component_clearance.rs` (`component-clearance`) places a fixed box or cylinder on a stated side of each component's placement frame. The front is the rule's `front_axis` or the source's `ObjectFront::Stated`, never inferred; `swing`/`-swing` take it from the door's leaves (`door_swing::swing_side`: one horizontal opening direction, no double-acting leaf), and `align` `handle`/`hinge` from its single hinged leaf's closed direction, resolved per side and refused on a side the leaf runs along. The volume starts at the component's directional extent, and every measured position is an interval: clear needs the union of all positions clear, obstructed needs their common part obstructed, anything else is not evaluated. Undecided obstacles are sent as candidates, so a clear volume stands, and an obstruction by them alone is re-asked without them. Protrusion shrinks the checked volume on every plan side; `within_space` uses `assess_containment` on the declared volume. A floating volume (`slide_from`, `slide_to`) is a placement search in the `space_path` spaces with a frame-offset domain anchored on the component: a witness for the volume grown by the position interval (and the slack off the line) passes, a proof of absence for the shrunk one without undecided obstacles is a finding. `front_axis` `against-wall` derives the front through `wall_sides.rs` (internal, the one reader of `measure_side_distances`): the side of the least-area rectangle whose nearest wall, from the side, is surely nearer than every other side's is the back; possibly present or undecided walls only lower a side's lower bound, a tie or no wall is `front not decided` (not evaluated), and the derived front is inexact evidence naming the wall. A rectangle's axis error widens the volume by the arc its points may sweep about the centre (`Turn`); never drop it. The volume is kept as edge intervals (`Plan`, base and top), so sizes from the component (`Sizing`: `component_plus`, `component_clamped`, measured per side in `Faces::size`), `depth_from` `midline` and a `top_datum` enter the union (outermost ends) and common part (innermost ends) without a separate size interval; never recentre a box from a size interval. `depth_slide_*` is the frame-offset domain's forward interval, as `slide_*` is its right one; an axis without a slide carries the witness slack. `quantifier` `any` combines each side's questions in `any_side`: a side passes only when all pass, a finding needs every side surely failing. `support_selector` asks `assess_support_coverage` on the declared volume: the union against sure supports within the band every base shares, the common part against every possible support within the band any base reaches; never with a floating volume. Keep fixed and floating volumes on the one three-valued `Freedom`, so `size_mode` `maximum` swaps the verdict (free is the finding) in one place; a maximum is one volume larger by the tolerance per dimension, never a measured largest volume.

`centre_line_distance.rs` (`centre-line-distance`) judges the distance from a footprint's least-area-rectangle centre line to the nearest `wall_selector` wall on each side through `wall_sides.rs` (never its own reading of side distances): too close needs a sure wall surely nearer than the minimum, too far every possible wall farther than the maximum (or none within it), no wall nearby nothing listed within `reach`; a pass needs the lower bound over every possible wall at least the minimum and a sure wall within the maximum. `against-wall` takes the back from `Walls::back`, so a tie is never broken; `long`/`short` need `long_axis`. Walls beyond `reach` are none, so `reach` must hold both bounds.

`component_visibility.rs` (`component-visibility`) places the eye `eye_height` above the component's exact base over its exact footprint centre and asks the line-of-sight service about every target (selected or undecided) with the range. A target is surely in view only when selected, surely in range and visible past every possible blocker; it is hidden only when the certain blockers hide it (a hidden answer naming an undecided blocker is re-asked without them). Everything else is undecided and decides only what it cannot change. The component and the target never block. Transparency is the `blockers` selection's, through `axioval:presentation.Transparency`; never add a threshold here.

`effective_coverage.rs` (`effective-coverage`) sends each element's near sources (plan broad phase within the range, or the touch tolerance) and blockers overlapping it in plan to `PlanAreaService::measure_coverage`, sources certain only when selected (and, in `touching`, surely touching by the horizontal distance), blockers certain only when selected; sources never block. A source whose extent cannot be read raises the upper bound to the whole footprint, a blocker whose extent cannot be read drops the lower bound to zero. The share is judged with `plan_area::judge`; the capacity check sums each source's capacity times its multiplier (constant or `capacity_multiplier_property`) over sources whose effect meets the footprint, a missing value leaving only the side it cannot change. `area_property` replaces the footprint's area in both checks. A value not stated (absent, null, blank) is its own `missing value:` finding (the element's area, then nothing else is checked; a surely contributing source's capacity or multiplier, relating it); a value of another kind is not evaluated, never missing. Connections (`access_path` and the `space_access` selectors, `travel` and `visible` only) come from `AccessIndex::connections` and go into the request with `CoverageRequest::with_connections`, undecided elements as uncertain; an element whose spaces cannot be read keeps the upper bound at the whole footprint like a blind source. With connections, blockers are gathered within `range` of the element, not only overlapping it.

`body_facts.rs` (internal) reads the reserved body set (`axioval:body`) by the engine's own names, never through concept binding, citing every fact read; capabilities judging how a body is modelled go through it. `allowed_profile.rs` (`allowed-profile`) matches a member's one swept profile against the `profiles` table: any fitting row passes, an undecided row (a refused dimension) leaves the object not evaluated unless another fits, and a finding says which of the three results it is (wrong geometry, arbitrary profile, not an allowed profile) and names the nearest row, which only words the message. The generic dimension columns map onto family parameters in `parameter`; a row's dimension the family lacks, or the source leaves unset, does not fit, and a schema default is never assumed. A mirrored profile is its parent's; a derived one is not evaluated.

`opening_zone/` (`opening-zone`) places each opening in its host's face from both bodies' facts: the host a straight extrusion perpendicular to its profile with a bounded outline (sections centred on their position, or a free polygon), the opening a straight extrusion of a rectangle, rounded rectangle, circle, ellipse or free polygon, its extents the exact support of its outline swept along its extrusion. `opening_zone/outline.rs` owns free outlines (`Profile.OutlineX`/`OutlineY` and voids): `Polygon::new` refuses anything that is not one region, and `clearance` decides where a rectangle in the section plane lies against it (inside, and its clear distance each way over its whole width). A host of a free outline is bounded by it where the face crosses it (`Host::section_rect`, `Host::clearance`): containment and end or edge distances are exact only for an opening extruded straight through the host (`Placed::section_exact`); otherwise they may pass but never find. Never chord a curved outline; the source refuses it and the capability is not evaluated. Anything else is not evaluated, never approximated. Within the host and each declared zone (ends, edges or flanges) are separate findings; spacing is exact only between two axis-aligned rectangles extruded through the host, otherwise the extents' distance is a lower bound that may only pass. An opening of unknown host or undecided selection is a possible neighbour. `opening_zone/face.rs` owns the body-set geometry `opening-zone` and `opening-area` share (host face, opening and member solids, inner and outer extents); never read body facts for either elsewhere. `opening_zone/supports.rs` finds a host's supports by `support_path` and by contact (`ProximityServiceHandle`, `Minimum3d` within `support_gap`), never by guessing from geometry alone, and reads each from the body set: a boxed section's extent is an inner and an outer interval (`Outline::reach`), and only a projection known to be a rectangle has an inner footprint. A finding needs the inner interval and a decided support (relation and selection); a pass needs the outer; anything else is not evaluated, naming each member, and a sure finding stands beside undecided members. `opening_area.rs` (`opening-area`) sums the areas openings take from a host's middle plane: only straight extrusions through the host from an exact, non-hollow section in the face (a free polygon less its voids), wholly within it (inside a free host outline, not only its box) and clear of each other's extents; a recess short of the middle plane counts zero, one reaching it within rounding is not evaluated. Neither area stated is not checked, one is not evaluated.

`comparison.rs` owns the session diff behind `axioval compare`. It is a host entry point, not a capability: it needs two sessions. Match by external identity scheme only, never by `ObjectId`. Report unidentified objects, ambiguous identities and unreadable facets; never compare an unknown as empty. The spatial facets (placement, geometry, coordinate systems) are opt-in and read only typed services (`ObjectFrameServiceHandle`, `ProximityServiceHandle`, `CoordinateSystemServiceHandle`). Every measure is an interval judged by `Outcome::measured`: changed only when the whole interval exceeds the tolerance, unchanged only when none of it does, otherwise undetermined; never round a straddling interval. Geometry widens the bounds shift by both chord deviations; bodiless (`ProximityError::NoBody`) on both sides is agreement, `Unavailable` is unresolved. Do not implement a mesh difference here: a certified Hausdorff distance is axiolid/kernel#148. The report's rule ids (`RULE.added`, `RULE.<facet>`, `RULE.identity`) are a CLI contract.

Severity bands are the runtime's (`axioval_engine::Deviation`); a capability only reports how far each finding misses its bound with `push_graded_finding` and declares `grades_deviation`. Measure the deviation from the measured interval against the declared bound (never the slack-widened one), with `plan_area::deviation` for bounds judged by `plan_area::judge`; a finding naming several failing values grades by the worst (`Deviation::worst`), one that any of several rows would clear by the nearest (`Deviation::least`). A finding with no bound to miss is pushed ungraded.

`refine.rs` (`Refiner`, installed by `register_builtins`) applies what a rule instance declares about its outcomes and that reads the model, after the runtime graded severities. Severity overrides are tried in order over the finding's subject and related objects with `selection::selector_matches`; an undecided override keeps its severity possible, and a finding whose possible severities disagree becomes a not-evaluated outcome on its scope, never a default. Categories follow, through `support::category_headings` (the nested form of `category_prefix`: each level keeps its place with `[-]`, an unreadable level is an error). Keep every refinement generic: never read a capability's parameters or special-case a capability here.
