# `axioval-rules`

Maintained source-neutral capability policy and shared rule algorithms.

Capabilities may depend on Axioval IR and typed host-service interfaces, never concrete OpenBIM, ICDD, Axiolid, STEP, or vendor CAD types. Source interpretation belongs in adapters.

Every capability `register_builtins` registers needs an entry in `catalogue_texts.rs` (label, help and help for each parameter, English and German, sorted by id); its test and the golden catalogue (`tests/golden/catalogue.json`, regenerated with `AXIOVAL_BLESS=1 cargo test -p axioval-rules --test catalogue`) fail otherwise.

`property_rules.rs` owns property compliance policy; `selection.rs` owns fail-closed selector evaluation. `select_objects` and `object-count` take their population from `selection::population`: the project's objects, then the resource objects the selector reaches (`ResourceObjects::reached`), and a source whose reached resource objects cannot be listed is not evaluated as a whole; never iterate `project.objects()` for a rule's applicability elsewhere without deciding whether resource objects belong. Look an outcome's object up with `selection::object_by_id` (the refiner's overrides and categories), and place a resource object nowhere (`Locator`). A `ruleOutcome` selector reads the runtime's `RuleOutcomes` (`RuleOutcomes::selects`): an object the other rule left undecided is `IncompleteEvidence`, never a match or non-match, and without the service it is `MissingService`. `Refiner::evaluate_selector` is the runtime's one way to evaluate a selector; keep it on `selector_matches`. `bound_property_request` passes a derived set's property name through unbound (`is_derived_set`). A `PropertyValue::Measured` interval compares only where every value it may take agrees (`support::interval_verdict`, in selectors and `property-comparison`); a straddling interval is `IncompleteEvidence` (`support::undecided_reason`), never a match or a mismatch. A `derivedClass` selector reads `Arc<Classifications>` through `Classifications::selects`; outside a run it is `MissingService`. `unclassified.rs` (`unclassified-object`) reads `Arc<Classifications>`: unclassified is a finding, undecided is not evaluated with the row's reason. Both must resolve property values and absences through `PropertyResolutionServiceHandle`. Never infer absence from a missing `Object.properties` entry, and never silently skip an object when a property selector cannot be resolved exactly. A property selector whose value has another type than it compares is not evaluated, never a non-match; `matches` and `like` match the whole value. A list, bounded or table value is compared only by its stated values (`PropertyValue::stated_values`) under the selector's `quantifier`, never as a whole; `all` never holds vacuously. A `discipline` selector reads `SourceDisciplines`; a source without a declared discipline is `NotRecorded` with a source-only message (collapsed once per rule and source), never a non-match. A match on a mapped discipline cites the map rule and value (`DisciplineOrigin::locator`) as inexact evidence. A `source` selector reads `SourceMetadataIndex` the same way: an unread field is `NotRecorded` once per source, a field read and empty is an absent value (no operator matches), several values need `quantifier`; it compares through the same `Test` as property selectors. `isEmpty` and `isNotEmpty` mean `property-requirements`' `empty` and `not-empty` (`support::undefined`), judge the value whole and are false for an absent property. A `classification` selector's `codePattern` is an XML Schema pattern compiled by `xsd_pattern::compile` and matched as `classification` (the capability) matches codes; without `code` or `codePattern` it tests the system alone. A `related` selector walks its `path` with `support::Traversal`; a refused relationship answer or an undecided reached object leaves the candidate undecided, never excluded, and its `all` never holds vacuously either. `property-exists` means exact presence even when a source value is null or blank; `property-required` is the stronger non-empty contract and treats exact absence, null, and blank text as violations without converting adapter failures into findings. `property-data-type` adds the source-declared type to that contract; an unreported type is not evaluated, never a match. `PropertyResolutionError::UnreadableValue` is a present, non-empty property of an exact declared type whose value is unknown: `property-exists`, `property-required` and `property-data-type` decide on it, `property-value` fails only a `data_type` it does not declare (`judge_unreadable`) and otherwise leaves every value constraint not evaluated; everything else maps it through `selection::property_error` to `IncompleteEvidence`. Never compare or default its value. `PropertyValue::Complex` is present, not empty and of no type: `property-data-type` and every `property-value` type or value constraint fail it (`judge`), `property-predicate`, `property-comparison` and `property-value-equals` never pass it, and a property selector comparing its value leaves the object undecided. A table whose columns declare different types (`Property::column_types`) has the type of either column, and `property-value` with a `data_type` judges only the cells of the columns declaring it (`property_value::typed_cells`); no such column is a finding. Dates and date-times compare only through `support::temporal_order`: dates as XML Schema orders them (`Date::cmp_timeline`), date-times as instants, and a date-time with a date only at declared `day` precision, never by a default. A zoned and an unzoned date within 14 hours are incomparable (`Ok(None)`): `support::temporal_holds` answers equality (unequal) and leaves an order not evaluated, never guessed. `property_value.rs` owns `property-value`: lexical constraints cast to the resolved value's kind. A literal or constraint that does not fit the value is not evaluated, never a pass or a violation. A composite value needs `quantifier`; under `all` a bounded value open on a bounded side fails, since a range holds every value between its ends (keep this in step with `property-requirements`). A quantity is compared only under `si_units`, never as a bare number by default. Name patterns (`propertyPattern` selectors, `property_pattern` of `property-value`, the pattern columns of `property-requirements`) are XML Schema patterns compiled by `selection::xsd_name_pattern` and matched against source names through `bound_enumeration_request`, which binds only exact names through the package vocabulary; a pattern is never a concept. A `propertyPattern` selector with no match is no match, even under `matched: all`. `xsd_pattern.rs` translates XML Schema patterns; refuse any construct it cannot map exactly rather than approximate it. Its `translate` is public as `translate_xsd_pattern` so package importers write `matches` selectors with the same meaning; keep one translation.

`support.rs` holds the shared parameter reader, exact property resolution, relationship traversal and finding construction; new capabilities use it rather than re-reading `CompiledRule.parameters` by hand. A parameter present with the wrong type is an invalid declaration, never "absent". A capability forming one scope per source takes its sources from `support::sources` (the runtime's `SessionSources`), never from the objects alone, so an empty source is judged instead of silently passing. `support::table` reads table rows and owns row matching (first, most specific, all); capabilities use `match_rows` rather than reimplementing it. It fails closed on undecided rows and reports ties for the most specific row instead of breaking them by order. `property_predicate.rs` and `property_comparison.rs` take exactly one target (none only for the presence operators); keep that check when adding target kinds. A `property-comparison` range takes exactly one minimum and one maximum (`Bound`: a constant or a property of the checked object); two constants must be of one kind, and date bounds compare only through `support::temporal_order`, a value outside either bound being outside the range whatever the other leaves undecided. `property-comparison` compiles `like` and `matches` with the property selectors' wildcard translation in `selection.rs`, so a word means the same in both; `support.rs` owns the nearest-container climb behind `same_space`/`same_building`. The semantic capabilities (`conformance.rs`, `unique_value.rs`, `consistent_value.rs`, `counts.rs`, `object_count.rs`, `relative_count.rs`, `name_sequence.rs`, `numbering_consistency.rs`, `manual_issue.rs`) read properties, classifications and relationships only. `object-count`'s `disciplines` reads `SourceDisciplines`: a source of another discipline is not counted, one declaring none is never skipped (not evaluated per source, undecided across sources). An undecided selector or value is a not-evaluated outcome, and a count is judged only when the undecided objects cannot change the verdict. `consistent-value`'s `tolerance`/`tolerance_quantity` judge a numeric group by its range with every interval at full width: consistent only when the widest range is within, inconsistent only when the narrowest is beyond, otherwise the group is not evaluated; outliers are measured from the median interval the same way, never from a midpoint. Test them against the in-memory source in `tests/common/mod.rs`. `plan_area.rs` (`area-ratio`, `plan-coverage`, `plan-area`) and `level_spacing.rs` judge measured intervals: a verdict needs the whole interval on one side of a bound, and a straddling one is not evaluated. `area-ratio` and `plan-area` measure footprints or, with `measure: facade`, facade areas; keep the two behind `plan_area::Measure` rather than a second capability. `area-ratio`'s `numerator_measure` and `denominator_measure` (`Measure::sides`) measure each side on its own and never combine with `measure`. `space-validation`'s `maximum_unallocated_share` divides the sum of a storey's unallocated regions by the gross floor area the service states (`UnallocatedRegion::floor_area_square_metres`, the same on every region of a storey); without one the share is undefined and not evaluated. `level-spacing` measures the highest level from its contents' vertical extents and compares spaces with their level's height; only exact heights decide the prevailing one. `space_elevation` compares each level's spaces' bottom or top elevations with the prevailing exact one among them (`prevailing`, as for heights); heights are measured only when a check needs them. `light_area.rs` is `area-ratio`'s `light-area` numerator mode, not a capability: its fallback (stated, table, frame allowance) moves to the next step only on an exact absence, never on an error or a wrong-typed value, and records the step in each area's evidence; keep it a mode so the ratio's judgement stays in one place. `measure: facade` with `light-area` is an invalid declaration. `level-spacing` (`levels`, `spaces`), `plan-area` (`areas`) and `area-ratio` (`ratios`) report every measured value as a report table, passing or not, without a parameter (a new parameter would break every definition's signature); keep the table names and column ids stable, they are a report contract.

`classification_requirement.rs` (`classification`) states what a `classification` selector cannot: a system alone, systems and codes as XML Schema patterns, optional and prohibited. It reads the same `ClassificationServiceHandle` and decides as the selector does: one assignment meets the system and the code together, codes match the whole ancestor chain, and an assignment without a stated system is undecided when it could change the verdict, never a match or a non-match. Keep the two in step.

`table_allocation.rs` (`table-allocation`) assigns each object to one row through `support::table::match_rows`; an object that might belong to a row it was not assigned to (tie, undecided key or selection) leaves that row's count and area not evaluated unless an excess already stands. Never break a tie or skip an undecided object. Its key-cell helpers (`key_cells`, `read_keys`, `read_key`, `test_keys`) are shared with `group_composition.rs` and `clash_matrix.rs`; change them in one place. They hold `KEY_COUNT` (four) keys; each capability declares the key columns and parameters it takes (clash-matrix three), so widening the arrays never adds a parameter. With `anchor_key`, rows apply per anchor: assignment is per set of applicable rows (`Allocator`), an object reported extra or undecided once. `area_mode` `each` makes a row's area a three-valued match condition per object; never judge it on a midpoint, and never also sum it.

`quantity_takeoff.rs` (`quantity-takeoff`) reports a grouped `takeoff` table and never a finding. Group keys go through `support::category_headings` (the rule categories' reading: joined values, `-` for none, an unreadable key an error); never key groups another way. An object whose selection is undecided is a possible member of its group, one whose key cannot be read a possible member of every group of its scope: both widen `count` and every aggregate (a sum by `[min(0, lower), max(0, upper)]`) and are reported not evaluated, never dropped. A member's absent or unreadable value makes that aggregate `unknown`; `min`, `max` and `mean` of a group without a sure member are unknown, and `mean` is bounded greedily over the possible members (`extreme_mean`). Values of one measure in two kinds leave it unknown and the rule not evaluated; the column kind is the values' one kind, or the measured name's. Keep the table name and the `count` and `<aggregate>_<name>` column ids stable: they are a report contract; add columns, never rename one. Column kinds (`measure_<n>_kind`) only read values into `Cell`s: `related` walks `Traversal::path` (the selector path grammar) and sums numbers or lists texts, `boundary_area` reuses `space_boundary_coverage::coverage_error` over `BoundaryCoverageServiceHandle` (one request per space, however many columns), `property_set` uses `selection::enumerate`, `profile` reuses `allowed_profile::read_profile` and `dimension_value`; never read these a second way here. An expanding column's parts are ordered (property name; profile type, name, then `allowed-profile`'s dimension order) and its text parts only list `values`. A `values` aggregate counts a possible member's value only where it is listed already. A value that is absent is never zero. Every column states its exactness (`ColumnExactness`): `bounded` as soon as one value read is not exact. `quantity_takeoff/expression.rs` owns `computed` columns: a hand-written parser and unit algebra (SI exponents, the radian apart, one currency) bound once in `Declaration::parse`; never evaluate an expression as code or add a general-purpose language. Units are checked at binding only, so every input must have a unit known then (`measure_<n>_unit`, a measured name, a boundary area, a profile dimension, an earlier computed column). A computed value is per member, then aggregated: an input with no value gives none (never zero), a divisor whose interval holds zero gives none, and evaluation is plain interval arithmetic over the inputs' bounds.

`group_composition.rs` (`group-composition`) allocates each group's members to requirement entries by a maximum bipartite matching (`Allocation`), never greedily. Report only what every maximum matching agrees on: competing short entries share one shortfall finding, competing surplus members one surplus finding. An undecided membership, member key or group key leaves the group not evaluated; an ungrouped object is found only when every group that might reach it was walked. Group keys (`group_key_1`, alias `group_key`, to `group_key_3`) test the `group`, `group_2` and `group_3` cells through `Declaration::group_tests`, shared by row selection and `report_absent_groups`; an absent row is a project finding only when no group of undecided selection or key might match it.

`keyed_limit.rs` (`keyed-limit`) selects one row of a keyed limit table per object with `match_rows` (most specific) and reuses `plan_area`'s footprint and interval judgement. Its `member-plan-area` quantity sums members through `plan_area::member_areas`, the same traversal and population as `plan-area` with `member_selector`; never walk members here, and let undecided members stand only behind an excess. A key it cannot read exactly (absent, blank, another type, reached on no object, or disagreeing across reached objects) is unknown, never a non-match; no matching row is a "no limit defined" finding, and a tie is not evaluated. Its `sill-height` quantity judges the object's bottom against each floor `floor_path` reaches separately, through `level_spacing`'s vertical-extent helpers and `plan_area::judge`; any failing floor is a finding, otherwise an undecided floor leaves the object not evaluated. Keep sill heights a quantity, not a capability, so row selection stays in one place, and keep the elevation difference widened by `difference` so it always holds the exact value. Its `clear-width` quantity takes a stated clear width, then with `clear_width_from_leaves` `passage` the overall width less both linings and every hinged leaf's depth from the door's leaves (moving on on `NotStated`, a missing thickness or a leaf that does not swing), or `widest-leaf` the widest hinged leaf less the lining at each jamb its closed edge meets and its depth, else the overall width less the rule's `width_deduction`; like `light_area.rs`, it moves on only on an exact absence. The deduction is the rule author's approximation: keep it named in the message and cited by an inexact `axioval:derived.clear-width` evidence entry, and never default it or derive a clear width without it. `clear-height` deducts the declared `lining_thickness` and `threshold_thickness` from `overall_height`; a declared thickness the door does not state is unknown, so the clear height drops to a lower bound of zero, never a thickness of zero. `keyed_limit/threshold.rs` owns `threshold-step`: per reached space, the floor is the space's bottom unless a `ramp_selector` ramp is surely within `ramp_reach` (horizontal) and surely over the space (plan overlap); a ramp that only may be leaves the space's floor and the ramp's top both possible, and a side fails only when every possible floor fails. An unstated declared threshold widens the step to infinity above. Keep these quantities, not capabilities, so row selection stays in one place. `keyed_limit/defaults.rs` owns `door_type_defaults`: the first row whose `operation` (the leaves' operation) and `applies_to` match is the door's type, looked up only after the door states nothing (`DoorDefaults::lookup`), never for a value it states but that cannot be read; an undecided row before the first match leaves the door not evaluated, and every default used is worded in the message and cited by an inexact `axioval:default.door-type` entry. It stands in for the rule's `width_deduction` in `clear-width`, for an unstated declared lining or threshold in `clear-height` and `threshold-step`, and for an unstated fraction in `glazing-ratio`; `DoorClearWidth` and `door_clear_height` (shared with `local-circulation` and `escape-route`) take no defaults. `pair_key` reads one key per face of the object (`Keys::pair`) from the derived adjacency's sides (`adjacent_side`, never a stated relationship, which records no faces): a face recorded `:outside` is the reserved `exterior`, a space stating `exterior` is unknown, and rows match the unordered pair through `pair_test` (either order, specificity the named sides shifted by `PAIR_RANK` above the other keys); tied rows apply only when their bounds agree (`agree`). Without `pair_key` every key, message and tie behaves as before; keep it that way. `keyed_limit/measured.rs` (`DoorMeasures`) measures the door values through the quantities' own readers: `threshold_step` through `ThresholdStep::measure` (the same `sides` and `step_interval` `judge` reads, ramps by source kind), clear widths and heights cited `Rounded` where their evidence is exact and `Cited { exact: false }` where it is not, so an expression cites what the capability cites. `counts::same_ends` (`related-count`'s `same_ends`) compares the exact sets a path reaches from the anchor and each related object; an unreadable set is undecided, never different.

`property_requirements.rs` (`property-requirements`) checks every applicable row of a requirements table per object (`match_rows`, all rows; an undecided `applies_to` leaves the object not evaluated). Findings start with their result: `missing property`, `missing value`, `forbidden property present`, `forbidden value`, `wrong value`. Exact names resolve through `support::resolve`; a wildcard cell, a `property_set_pattern`/`property_pattern` cell (XML Schema) or a set-only row goes through `selection::enumerate` and `check_matched_row`: an included statement holds for every match and needs one (in every named set, through `selection::sets_without_match`, shared with `property-value`, which counts the enumeration's `empty_sets` among them), an excluded one for none, and a refused enumeration leaves the object not evaluated, never approximated from `Object.properties` or a permissive lookup. A set holds a property or is absent; a set-only row states only `defined`/`undefined`. `missing_set` refines a `missing property` to `missing property set` only on an exact empty enumeration of the set that reports no empty set either; a refusal keeps the plain result, which is true either way. A value condition that cannot judge a value (another kind, a unit mismatch, a straddling quotient) is not evaluated. A `requirement` row is internally a `state` row (`required` = include, `forbidden` = exclude, `optional` = include letting a missing value pass); keep one evaluation path for both. `ignore` rows are skipped before `applies_to` is evaluated and are never refused. `group_by_value` keys groups by row, category, result and the exact `support::value_key`; `category_property` goes through `support::category_prefix`, shared with `property-comparison`, and an unreadable category leaves the object not evaluated. Rounding (`decimals`) reuses `support::round_decimal` in the row's unit; without it bounds stay in canonical SI units so exact values are never rescaled. Exclusive bounds go through `plan_area::judge_bounds` (an interval touching an exclusive bound is not evaluated, never passed); date bounds only through `support::temporal_order`, and a row bounds numbers or dates, never both. `per` `measured-volume` and `measured-face-area` read `ProximityServiceHandle::measure_body_volume` and `FacadeAreaServiceHandle::measure_face_area` through `plan_area::body_volume`/`face_area`; a refusal leaves the object not evaluated, never divides by a guess.

`opening_spaces.rs` (`opening-spaces`) judges each door, window or opening by its host's declared exposure. An undeclared, null or non-boolean exposure, disagreeing hosts or no host leave the element not evaluated, never assumed internal. With the derived adjacency it reads sides only through `axioval_engine::adjacent_side`; never parse adjacency locators by hand.

`exit_separation.rs` (`exit-separation`) reaches each space's exits through `exit_path` among the `exit_selector` objects and judges pair separations against a fraction of the space's longest plan diagonal. Closest-point separation goes through `ProximityServiceHandle` (`Horizontal`), centres and farthest points through `PlanSpanServiceHandle`. An unknown flag widens the required interval to both fractions rather than guessing. `flag_sources` (or `flag` with `flag_path`, one source) is read in order and moves to the next source, then to `flag_default`, only on an exact absence (a path reaching nothing, or every reached object lacking the property); a refused read, a null, a non-boolean, a disagreement or a partial statement stops at unknown, never reading past it. An undecided exit can only add pairs, so only an `any` pass or an `all` failure stands with one. Never judge an interval by its midpoint.

`corridor_end_openings.rs` (`corridor-end-openings`) judges each opening `opening_path` reaches from a selected corridor against every end wall `PlanSpanServiceHandle::measure_corridor_ends` returns: in the wall when the whole gap lies within `wall_depth` and the whole facing beyond `facing`, out when either lies wholly on the other side. An undecided end wall or straddling interval leaves an opening not found elsewhere not evaluated, never passed; a selector-undecided opening is not evaluated only where it would be found. Findings are on the opening and relate the corridor. Never guess an undecided wall from the end's point or the space's shape.

`space_access.rs` (internal) reads direct access for `space_connection.rs` (`space-connection`), `space_distance.rs` (`space-distance`) and `effective_coverage.rs` (`effective-coverage`, `connections`): each door or opening reaches its spaces through `access_path`; with the derived adjacency the spaces must lie on opposite faces (read with `adjacent_side`) and a face entering no space is the outside, which a stated relationship can never show. A link through an element of undecided type, or any element whose spaces are unreadable, is unknown, never "no"; keep every capability on this one reader (`local-circulation` reads a space's entrances with `AccessIndex::entrances`). `space-distance` bounds the nearest distance from above by surely qualifying destinations and from below by every possible one (an unmeasured one counting as zero), so a refused route decides only what it cannot change; a blocked route is no destination. Walking starts at an exact footprint centroid inside the footprint (`space_distance::representative_point`, shared with `escape-route`) on the space's exact floor; never substitute another point for a centroid outside it. Walking takes two `nearest_target` queries, the sure destinations for the upper bound and every possible one for the lower; never go back to routing pairs one by one. `closest` measures pair by pair like `straight`, through `ProximityServiceHandle::measure_distance` (`Minimum3d`), never a plan distance: bodies stacked on two storeys are not zero apart.

`escape_route.rs` (`escape-route`) picks the first `uses` row per space (`match_rows`, first) and reaches exits as `exit-separation` does (its `Candidates`). Travel is a point's walking line to the exits' representative points: `farthest_point` over the space for `farthest-point`, `nearest_target` from each door for `door`; the sure exits bound it from above, every possible exit from below, and an exit without a point drops the lower bound to zero. With doors, a finding needs one sure door too far, a pass every possible door. The occupant load rounds the footprint interval up at both ends and takes every `widths` row between them; a stated clear width decides both ways, a footprint's longest plan diagonal only a failure. `sections` factors (at least one) bracket the multiplied travel between the plain walk's lower bound and an upper bound: the plain upper bound times the largest factor of a section the walk may cross (only a section whose horizontal distance from the start surely exceeds that upper bound, or a `shared_by` section fewer checked spaces (sure, undecided or unreadable) could reach along `section_path`, is left out), or, from a door, where tighter, the answer's own walk traced over the sections (`walked_cost`: the plain upper bound plus each section's traced upper length times its factor less one, an untraced section counting the whole walk). The traced walk bounds only from above: never lower the lower bound from it, and never trace from the farthest point, whose witness is a point, not a walk. Where the backend weighs travel (`weighted`, on one level or climbing the rule's connectors), the same walk or farthest point is asked with `TravelCost`s: every possible section for the upper bound (`Travel::weighted`, taken where smaller), only sure sections (`Section::sure`: surely picked and no `shared_by`) for the lower bound, taken where larger and named in the finding (`Travel::weighed`); a refusal keeps the plain bounds. Never weigh the lower bound by a section that only may multiply. Passages (`passage_selector`, reached along `passage_path` or the space itself) carry the summed loads of every checked space reaching them, and are judged per passage in `judge_passages`, merged into the passage's own outcome when it is a checked space; a possibly reaching space with an unknown load leaves the passage not evaluated. With `walked_passages` (`walked`, `door_passages`) a space surely relies on a passage only when from every door the walk to every possible exit avoiding it (`with_avoided`) is longer than the plain walk's upper bound to the sure exits or unreachable, with every exit placed and one sure; the witness walk's trace only picks the candidates, never proves reliance, because shortest walks may tie. It may rely on every passage not ruled off by the door-to-passage-to-exit plan distances exceeding that upper bound, or by `forced_off` (the walk from the start to every possible exit forced through it, around only sure avoidances with every target placed, longer than that bound or never entering it); anything unwalkable may rely on every passage. Walks start at an `Origin` (an object's representative point, or a given point); a space measured from its farthest point that reaches no door walks its passages from the farthest point's witness (`farthest_witness`, `start_passages`), never when it has doors. Sure loads count in `least`, possible ones only in `most`, and a passage no space surely relies on is never a finding. A stated `passage_width_property` decides both ways, the shorter side of a uniquely oriented least-area rectangle only a failure. `exit_door_direction` judges each exit door with `door_swing::relation` against the checked space: `Into` a sure exit is a finding, `Away` and `BothWays` pass, an exit that is not a door is skipped, and a sure door without a hinged leaf, unknown leaves or `Apart` leave the space not evaluated; never read `Apart` as opening away. `no_escape_selector` goes through `Reached::without` (a sure pick is no exit or start, an undecided one only possible) and `Avoid`: every walk's upper bound keeps out of every possible pick, its lower bound only out of the sure ones; the farthest point is measured on the plain walk, a lower bound always, an upper bound only when `farther` proves every avoided object out of reach. Never let an avoided walk fall back to the plain one. Compartments (`assigned`, cached per space: along `compartment_path`, or by the overlap interval against `compartment_overlap`, a straddling share undecided) end travel at the doors out of the start's one sure compartment (`boundary`): its spaces are walked through `door_path` and back (`Traversal::reversed`), sure members before possible ones; a door reaching a space surely outside (not surely avoided) or no other space leads out, anything undecided on the way makes it only possible, and an unreadable door or space clears `Escape::known`, dropping the lower bound to zero. No compartment in the project is one inadequate-information finding per source of a checked space (`no_compartment`), and the spaces stay not evaluated. `exit_count: routes` (`routes`) bounds independent routes from above by the targets a walk may reach (proven unreachable ones out) and by one where the nearest walk crosses a passage whose detour reaches no target (unreachable, never merely longer), and from below by sure targets whose own traced walks cross pairwise disjoint passages (an untraced walk shares every passage). Passages without `passage_width` only trace routes (`Passages::judged` false): never judge their widths. `route_door_direction` and `minimum_clear_height` (`route`) judge what the named walk from each start door crosses (`crossed` over `door_selector` objects and passages), the start door against the space with `door_swing::relation` and the space itself; a failure is a finding only with `on_every_walk` (the detour around it, avoiding only the sure objects, longer than the witness or unreachable), otherwise a doubt. Direction comes from `crossing`, the walk's passage over a closed leaf's line within a leaf's width; crossings both ways or none are undecided. `NotStated` leaves are an undefined direction (a failure); a door without a single-swing leaf is not judged. Heights: `keyed_limit::door_clear_height` (the `clear-height` quantity's reading, never a copy of it) as an interval, a `SpaceService` clear height both ways, the vertical extent only a failure. `common_path_factor` adds `(factor - 1)` times the common path to each start's upper bound only: the whole walk, or from a door the named walk's traced length over passages every other sure target's walk may cross too (`common_length`; an untraced walk shares everything, no other reachable target makes the whole walk common). A rectangle's axis error widens the volume by the arc its points may sweep about the centre (`Turn`); never drop it. The volume is kept as edge intervals (`Plan`, base and top), so sizes from the component (`Sizing`: `component_plus`, `component_clamped`, measured per side in `Faces::size`), `depth_from` `midline` and a `top_datum` enter the union (outermost ends) and common part (innermost ends) without a separate size interval; never recentre a box from a size interval. `depth_slide_*` is the frame-offset domain's forward interval, as `slide_*` is its right one; an axis without a slide carries the witness slack. `quantifier` `any` combines each side's questions in `any_side`: a side passes only when all pass, a finding needs every side surely failing. `support_selector` asks `assess_support_coverage` on the declared volume: the union against sure supports within the band every base shares, the common part against every possible support within the band any base reaches; never with a floating volume. `depth_mode` `less_clear_width` (`Sizing::LessClearWidth`) reads the door's clear width once per door through `keyed_limit::DoorClearWidth::measure` (never a second reading) and maps its interval to a depth interval (`max(minimum, total - width)`, decreasing, widened by `keyed_limit::difference`), which enters the union and common part like any measured edge; an unreadable width leaves every side not evaluated, and `ClearDepth::annotate` names the depth's source on every outcome. Keep fixed and floating volumes on the one three-valued `Freedom`, so `size_mode` `maximum` swaps the verdict (free is the finding) in one place; a maximum is one volume larger by the tolerance per dimension, never a measured largest volume.

`centre_line_distance.rs` (`centre-line-distance`) judges the distance from a footprint's least-area-rectangle centre line to the nearest `wall_selector` wall on each side through `wall_sides.rs` (never its own reading of side distances): too close needs a sure wall surely nearer than the minimum, too far every possible wall farther than the maximum (or none within it), no wall nearby nothing listed within `reach`; a pass needs the lower bound over every possible wall at least the minimum and a sure wall within the maximum. `against-wall` takes the back from `Walls::back`, so a tie is never broken; `long`/`short` need `long_axis`. Walls beyond `reach` are none, so `reach` must hold both bounds.

`component_visibility.rs` (`component-visibility`) places the eye `eye_height` above the component's exact base over its exact footprint centre and asks the line-of-sight service about every target (selected or undecided) with the range. A target is surely in view only when selected, surely in range and visible past every possible blocker; it is hidden only when the certain blockers hide it (a hidden answer naming an undecided blocker is re-asked without them). Everything else is undecided and decides only what it cannot change. The component and the target never block. Transparency is the `blockers` selection's, through `axioval:presentation.Transparency`; never add a threshold here.

`effective_coverage.rs` (`effective-coverage`) sends each element's near sources (plan broad phase within the range, or the touch tolerance) and blockers overlapping it in plan to `PlanAreaService::measure_coverage`, sources certain only when selected (and, in `touching`, surely touching by the horizontal distance), blockers certain only when selected; sources never block. A source whose extent cannot be read raises the upper bound to the whole footprint, a blocker whose extent cannot be read drops the lower bound to zero. The share is judged with `plan_area::judge`; the capacity check sums each source's capacity times its multiplier (constant or `capacity_multiplier_property`) over sources whose effect meets the footprint, a missing value leaving only the side it cannot change. `area_property` replaces the footprint's area in both checks. A value not stated (absent, null, blank) is its own `missing value:` finding (the element's area, then nothing else is checked; a surely contributing source's capacity or multiplier, relating it); a value of another kind is not evaluated, never missing. Connections (`access_path` and the `space_access` selectors, `travel` and `visible` only) come from `AccessIndex::connections` and go into the request with `CoverageRequest::with_connections`, undecided elements as uncertain; an element whose spaces cannot be read keeps the upper bound at the whole footprint like a blind source. With connections, blockers are gathered within `range` of the element, not only overlapping it.

`body_facts.rs` (internal) reads the reserved body set (`axioval:body`) by the engine's own names, never through concept binding, citing every fact read; capabilities judging how a body is modelled go through it. `allowed_profile.rs` (`allowed-profile`) matches a member's one swept profile against the `profiles` table: any fitting row passes, an undecided row (a refused dimension) leaves the object not evaluated unless another fits, and a finding says which of the three results it is (wrong geometry, arbitrary profile, not an allowed profile) and names the nearest row, which only words the message. The generic dimension columns (`DIMENSIONS`, lengths and slope angles) map onto family parameters in `parameter`; `match: per_dimension` (`per_dimension`) takes each stated dimension's allowed values from every row of the type and name, and a dimension no value fits is a finding whatever else is undecided; a row's dimension the family lacks, or the source leaves unset, does not fit, and a schema default is never assumed. A mirrored profile is its parent's; a derived one is not evaluated.

`opening_zone/` (`opening-zone`) places each opening in its host's face from both bodies' facts: the host a straight extrusion perpendicular to its profile with a bounded outline (sections centred on their position, or a free polygon), the opening a straight extrusion of a rectangle, rounded rectangle, circle, ellipse or free polygon, its extents the exact support of its outline swept along its extrusion. `opening_zone/outline.rs` owns free outlines (`Profile.OutlineX`/`OutlineY` and voids): `Polygon::new` refuses anything that is not one region, and `clearance` decides where a rectangle in the section plane lies against it (inside, and its clear distance each way over its whole width). A host of a free outline is bounded by it where the face crosses it (`Host::section_rect`, `Host::clearance`): containment and end or edge distances are exact only for an opening extruded straight through the host (`Placed::section_exact`); otherwise they may pass but never find. Never chord a curved outline; the source refuses it and the capability is not evaluated. Anything else is not evaluated, never approximated. Within the host and each declared zone (ends, edges or flanges) are separate findings; `edge_distance_maximum` (`far_edges`) finds an opening whose lower-bound distance exceeds the maximum and passes only an exact one; spacing is exact only between two axis-aligned rectangles extruded through the host, otherwise the extents' distance is a lower bound that may only pass. An opening of unknown host or undecided selection is a possible neighbour. An element reaching several hosts (a duct through beams along `axioval:derived.intersects`) is placed and judged in each (`hosts_of`, one `Placed` per host); a host whose body cannot be read leaves only that placement not evaluated. `opening_zone/zones.rs` judges `zones` as a union of rows: inside one zone passes, a finding needs every zone surely missed (exact distances; a lower bound only passes) and names and grades by the zone missed least; any zone the opening may lie in leaves it not evaluated. Distance findings are graded (`Found` carries the deviation); outside-the-host and support findings are not. An L host (a parameterised `l-shape` with straight edges, `l_outline`, or a six-vertex axis-parallel free outline) is its polygon; `Polygon::l_shape` gives its web zone (the height beside the notch) and web leg, and `Host::section_rect` clips the through span to the leg, so a hole through the web never crosses the notch. A rounded or sloped L stays boxed, without a web. `opening_zone/dimensions.rs` judges `dimensions` rows per placement: a target row measures the extents' gap to the nearest target in the same host (`Judge::neighbours`), the interval from every possible target (unknown places drop it to zero) up to the nearest sure one, and an edge row the host's clearance, exact or a lower bound; `Bound::judge` decides only when the whole interval holds or misses. Never break a tie between undecided targets. `minimum_opening_area` drops a placement surely below it before anything reads it (`place_in` returns `None`; `opening_area` returns `None`), from the section area only for an opening extruded along the through axis, else from its extents' box; a placement that may be small (`may_be_small`) is not evaluated and a possible neighbour, never ignored. `opening_zone/face.rs` owns the body-set geometry `opening-zone` and `opening-area` share (host face, opening and member solids, inner and outer extents); never read body facts for either elsewhere. `opening_zone/supports.rs` finds a host's supports by `support_path` and by contact (`ProximityServiceHandle`, `Minimum3d` within `support_gap`), never by guessing from geometry alone, and reads each from the body set: a boxed section's extent is an inner and an outer interval (`Outline::reach`), and only a projection known to be a rectangle has an inner footprint. A finding needs the inner interval and a decided support (relation and selection); a pass needs the outer; anything else is not evaluated, naming each member, and a sure finding stands beside undecided members. `support_distance_ratio` scales the distance per host (`SupportConfig::required`, from `Host::axis` along `length_axis` for `span`, `height_axis` for `depth`) into an interval widened by a rounding step each way: find below its lower end, pass above its upper end. Without the ratio the requirement and every message stay the fixed `support_distance`'s. `opening_area.rs` (`opening-area`) sums the areas openings take from a host's middle plane: only straight extrusions through the host from an exact, non-hollow section in the face (a free polygon less its voids), wholly within it (inside a free host outline, not only its box) and clear of each other's extents; a recess short of the middle plane counts zero, one reaching it within rounding is not evaluated. Neither area stated is not checked, one is not evaluated. `empty_host.rs` (`empty-host`) sums through the same `opening_area::voided` (keep one placement and overlap rule for both) and compares with the face on the middle plane (`face_area`: the box, the outline's area, or `Polygon::chord` times the height); a chord along an edge is undecided, never zero. `measured_openings.rs` measures `opening_area`, `opening_count` (the counted openings) and `middle_face_area` through `voided` and `empty_host::face_area`. `opening_zone/measured.rs` (`PlacementMeasures`) lists `opening_placements` through `Judge::place` and the judgement's own `beyond`, `crossing`, `end_clearance`, `edge_clearance` and `far_clearance`; never measure a margin another way. A lower-bound distance is stated as the interval up to the host's extent, so it passes but never finds.

`coordinate_consistency.rs` owns `coordinate-consistency` and `compare_coordinate_systems`, the one comparison of two sources' coordinate systems (world frame, true north, map conversion in metres, site placement) that hosts also use to decide whether two sources' geometry shares a frame (`CoordinateConsistency::shares_frame`). A statement only one side makes, an unknown site, an inexact map unit and an unreadable system are unknown, never agreement; a missing map conversion is `NotRecorded`, or a finding with `require_map_conversion`. Findings are scoped to the differing source and cite both systems' evidence. `comparison/` owns model comparison: `compare_sessions`, the host entry point behind `axioval compare` (two sessions), and the `model-comparison` capability (`capability.rs`, two sources of one session named by discipline); both run the one `compare` over two `Revision`s, so keep every facet in `facets.rs` and every matcher in `matching.rs`. Match by the request's matchers in order (a scheme, a property, then the pairwise `geometry`, `placement`, `overlap` and `related`), never by `ObjectId`. A pairwise match needs each object to be the other's one sure candidate with no undecided one; a straddling interval, a refused measurement or several sure candidates leave every object involved undecided, and an unmeasurable body every object of its kind on the other side. Pairwise matchers need one session (the two revisions share services); across sessions they refuse. Surfaces coincide only by the certified Hausdorff interval (never bounds alone, which only exclude), overlap by the certified shared volume against the larger body. A revised timestamp surely older is an error finding whatever the rule's severity; one without a UTC offset spans fourteen hours either way. Mirroring is read from `axioval:body.Mirrored` through `body_facts.rs`, never from frames, which are right-handed by contract. A key held twice matches nothing; an unreadable key leaves its object and every object of the other side the same matcher keyed but left unpaired undecided, never added or removed. Property sets are listed only through `selection::enumerate`; never read them from `Object.properties`. The capability reports under the rule's own id with the facet in the message (`Naming::Prefixed`); a change involving only objects the selector cannot decide is not evaluated. Report unidentified, ambiguous and undecided objects and unreadable facets; never compare an unknown as empty. Relationship kinds (`with_relationships`, `compare_relationships`) are listed once per kind and revision through `RelationshipSelectionServiceHandle::edges` (`facets::KindSide`), never per pair, and related objects are named through the matching (`related_names`): a pair's identity, a non-candidate's unique scheme identity, `removed`/`added` for unmatched ones, nothing for undecided ones. Only differences among named related objects are changes; an unmatched or undecided related object leaves the kind unresolved, never a change, and a refused kind is unresolved for every pair. The spatial facets (placement, geometry, coordinate systems) are opt-in and read only typed services (`ObjectFrameServiceHandle`, `ProximityServiceHandle`, `CoordinateSystemServiceHandle`). Every measure is an interval judged by `Outcome::measured`: changed only when the whole interval exceeds the tolerance, unchanged only when none of it does, otherwise undetermined; never round a straddling interval. Geometry widens the bounds shift by both chord deviations; bodiless (`ProximityError::NoBody`) on both sides is agreement, `Unavailable` is unresolved. `GeometryMode::Mesh` (`geometry: mesh` with `tolerance_metres`, `with_mesh_geometry`) asks the revised session's service for the body's surface (`body_surface`) and the base session's service to measure against it (`measure_surface_distance`), never computing a distance here; it is judged as `Measure::Mesh` with the evidence's witness (`Witness`, which the projection turns into `comparison:witness:…` evidence on the finding). A tessellated body on either side leaves the facet unresolved before anything is measured, unless both surfaces carry an exact boundary (`BodySurface::exact_boundary`): never widen a tessellation into a certified distance, and never treat it as unchanged. Evidence measured between boundaries (`SurfaceBasis::ExactBoundary`) is judged as `Measure::Boundary`, its finding citing both boundaries (`comparison:exact-boundary:<object>`, exact); the interval is sound however wide (the kernel's budget may stop it wider than asked), so `facets::surface_distance` judges it by `Outcome::witnessed` like every measure; never decide or refuse it by its width. The report's rule ids (`RULE.added`, `RULE.<facet>`, `RULE.identity`) are a CLI contract.

Severity bands are the runtime's (`axioval_engine::Deviation`); a capability only reports how far each finding misses its bound with `push_graded_finding` and declares `grades_deviation`. `refine.rs` (`Refiner`, installed by `register_builtins`) applies what a rule instance declares about its outcomes and that reads the model, after the runtime graded severities. The refiner keeps the level texts in `Finding::categories` beside the headings; the two never disagree. Keep every refinement generic: never read a capability's parameters or special-case a capability here.
