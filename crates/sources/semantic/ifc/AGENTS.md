# `axioval-ifc`

IFC source contracts, conformance doubles, and the production IFC2X3/IFC4 STEP evidence-session seam.

- `src/release.rs` decides the one release a file declares (`IfcRelease::from_header`) and holds each release's schema table and type-system identity. Every service receives that release; none may call `ifc4()`/`ifc2x3()` directly. IFC2X3 and IFC4 share entity names with different attributes and ancestry, so reading one with the other's table gives confident wrong answers, not errors.
- `src/ifc.rs` owns strict STEP parsing, IFC object adaptation, snapshot fingerprinting, the exact direct-property service (upstream `ifc-properties` ≥ 0.2.1, which binds per release), and session assembly.
- `src/relationships.rs` is the exact relationship-selection service. Relationship identities are entity names in the source's own release; end slots come from that release's schema (`ends_of`), never a hand-written table. Every answer carries a `relationship-scan` completeness locator.
- `src/integrity.rs` reports source irregularities through the same `read_instance` reader as selection. Keep them sharing one reader so a warning and a refusal always describe the same instances.
- Absent required ends (`$`) are recorded, not fatal: strict requests refuse, `AbsentEndPolicy::Skip` answers and cites each one, and integrity reports them as warnings. "Required" is per release: `IfcRelSpaceBoundary.RelatedBuildingElement` is optional in IFC2X3 and required in IFC4. Dangling or wrongly shaped ends stay hard refusals and integrity errors. Do not widen skip to cover those.
- `src/identity.rs` reads every `IfcRoot` GlobalId once per session. The same scan decides which objects carry the `ifc-globalid` alias and which integrity warnings are raised, so a missing alias always has exactly one warning. Never attach a GlobalId that is invalid or shared, and keep the `to_uuid`/`from_uuid` round trip until openbimrs/ifc#62 lands.
- `src/attributes.rs` answers the reserved attribute sets from the entity and from its `IfcRelDefinesByType` type object. Attribute slots come from the release schema, never a table. Text, enumeration, boolean, integer and unit-free real values are answered as stated; measures go through `measure.rs`.
- `src/temporal.rs` reads `IfcDate`, `IfcDateTime` and `IfcTimeStamp` as IR dates and date-times, for property sets and attributes. An `IfcDateTime` without a UTC offset is `Incomplete`, never read in a guessed zone or downgraded to text; malformed text is `InvalidValue`.
- `src/measure.rs` converts every measure through `ifc_properties::exact_unit` to SI. Never read a measure as a bare number, and never guess a unit when resolution refuses.
- `src/layers.rs` reads presentation layers for `axioval:presentation.Layer`: representations, their items, and mapped representations. Answer every distinct layer as a list; never pick one. A model without any layer assignment answers `NotRecorded` with a source-only message, never absence.
- `src/styles.rs` reads surface transparency for `axioval:presentation.Transparency` from body representation items: an item's own style (unique direct `IfcStyledItem`, else its styled layers, mirroring `ifc-style`'s `resolve_item_style`, pinned by a parity test) is authoritative; only items without a surface style fall back to the object's material styles, whose material ids come from `materials.rs`. Read shading and surface-style slots through `ifc-style`, never here. List every distinct value; never average or pick one. A surface style without shading states no transparency and is refused; no style is exact absence, never opaque.
- `src/materials.rs` projects `ifc-material`'s resolved assignment (occurrence first, then type) onto `axioval:material`. Never re-derive which association applies or read material slots here; that is the upstream crate's. Layer thicknesses go through `measure.rs`. A malformed member refuses the whole material, never a partial answer. IFC2X3 stays refused until `ifc-material` binds to the release (openbimrs/ifc#77).
- `src/classifications.rs` maps `ifc-classification` answers onto `ClassificationService`. Never read classification slots here: release-specific names, notations and hierarchy rules are the upstream crate's. An assignment with no stated system stays `system: None`; never infer one from names or locations.
- `src/frames.rs` answers object frames from `ObjectPlacement`. Placement chains are composed by `ifc-geometry`'s `PlacementResolver` (no features, so no geometry kernel); never re-derive the composition here. The origin goes through the exact project length unit, never `ifc_geometry::units::resolve`, which assumes metres when the file states none. IFC states no front: never report one from the placement's Y axis. `IfcGridPlacement` stays refused.
- `src/coordinates.rs` answers the source coordinate system from the one root `Model` context: `WorldCoordinateSystem` through `ifc-geometry`'s `axis_placement_transform` and the exact project length unit, `TrueNorth`, and an IFC4 `IfcMapConversion` of that context. Several model contexts or conversions are ambiguous and refused. An unstated or unresolvable `MapUnit` stays unknown, never metres; unset `XAxisAbscissa`/`XAxisOrdinate`/`Scale` take the schema defaults.
- Integrity cardinality warnings (`CONTAINED_TWICE`, `ZONE_MEMBER_NOT_SPATIAL`) come from `ifc-systems` anomalies; do not re-derive them from raw relationships.
- Preserve source-qualified identities and bind every evidence locator to the source fingerprint.
- IFC2X3 TC1 and IFC4 ADD2 TC1 only. IFC4X3 is refused until upstream exact property resolution covers it; do not add a local resolver for any release.
- Parse/model diagnostics, unsupported schemas, malformed traversal, conflicts, and unsupported values fail closed.
- Keep IFC dependencies behind the facade's optional `ifc` feature; never add Axiolid, geometry-kernel, rule-policy, path, or Git dependencies here.
- This crate adapts **IFC**, not the whole OpenBIM ecosystem. A future CityGML, GAEB, or IDS adapter is a new sibling under `sources/semantic/`, never a module added here.
- `UnavailableOpenBimImporter` remains the explicit conformance placeholder for host-defined importer implementations.
- Run `cargo test -p axioval-ifc` and strict clippy after changes. `tests/ifc_session.rs` is the production E2E contract; `tests/ifc2x3.rs` pins release binding; `tests/relationships.rs` and `tests/relationship_integrity.rs` pin the relationship and integrity contracts; `tests/identity.rs` pins GlobalId aliases; `tests/attributes.rs` pins attribute resolution; `tests/measures.rs` pins unit conversion; `tests/defined_types.rs` pins defined types and dates; the facade's `tests/ifc_dates.rs` compares IFC dates end to end; `tests/quantities.rs` pins quantity sets and the refusals around them; `tests/layers.rs` pins presentation layers; `tests/transparency.rs` pins surface transparency; the facade's `tests/ifc_transparency.rs` pins a blocker selector that leaves transparent objects out; `tests/materials.rs` pins materials; `tests/frames.rs` pins object frames; `tests/coordinates.rs` pins coordinate systems; the facade's `tests/ifc_layers.rs` pins layer agreement end to end; the facade's `tests/ifc_semantic_rules.rs` runs the semantic capabilities as a compiled package; the facade's `tests/ifc_classification.rs` pins classification selection end to end.
