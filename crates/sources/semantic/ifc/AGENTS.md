# `axioval-ifc`

IFC source contracts, conformance doubles, and the production IFC2X3/IFC4/IFC4X3 STEP evidence-session seam.

- `src/archive.rs` reads ifcZIP: every member path is checked (absolute, `..`, backslash, NUL, symbolic link refuse the archive), exactly one `.ifc`/`.ifcxml` member is a model (none, several or IFC-XML refuse), and the source document is `archive/member`. The member is read with `import_ifc_session`, never a second reader, so a zipped model answers every rule as the plain file does; `tests/ifczip.rs` pins it. `zip` is a normal dependency with `deflate` only.
- `src/xml.rs` reads ifcXML through `ifc-xml`'s `XmlCodec` (with the release's schema names) into the STEP reader's `Model`, then binds it through `ifc::session`, the one path after parsing, so an XML model answers every rule as its STEP form (`tests/ifc_xml.rs` compares the IR). `bounded` (quick-xml 0.42) refuses a start tag of more than 256 attributes or 8 namespace declarations before the codec parses; keep it first. The codec reads its own dialect and misreads others silently, so a read is proven before it is used: one supported schema, every entity declared, every XML attribute and attribute element named by the release or a position (`unnamed_values`, quick-xml), trailing omitted attributes padded unset, and `ifc_validate::type_check` without errors. Never relax a check without the codec refusing that case itself; never read an XML value in part. Source system `ifc-xml`.
- `src/release.rs` decides the one release a file declares (`IfcRelease::from_header`) and holds each release's schema table and type-system identity. Every service receives that release; none may call `ifc4()`/`ifc2x3()`/`ifc4x3()` directly. IFC2X3 and IFC4 share entity names with different attributes and ancestry, so reading one with the other's table gives confident wrong answers, not errors.
- `src/ifc.rs` owns strict STEP parsing, IFC object adaptation, snapshot fingerprinting, the exact direct-property service (upstream `ifc-properties` ≥ 0.5.0, which binds per release and reads quantity sets and predefined property sets), and session assembly. A quantity without a readable value (`$`, text, a truncated record; the permissive readers' `Quantity::Unresolved`) is refused by the exact API and so by `resolve` and `enumerate`: never 0, never absent. `IfcNumericMeasure` (IFC4X3 `IfcQuantityNumber`) is a plain number through `carries_exactly`. `enumerate` answers `PropertyEnumerationRequest`s through `exact_properties_where`, the same traversal and refusals as `exact_property`, and builds each property with the same `property` helper as `resolve`, so one set and one name enumerate exactly what they resolve; a set of a reserved name is never selected, and a selected value the IR cannot carry refuses the whole answer. A selected set whose members are `()` or `$` is found through `exact_property_sets_where` and reported in `empty_sets`, never refused; `resolve` answers a property named in it absent, and only when the refusal names that set and every set of the name is empty. Every other `MalformedAggregate` stays a refusal. Enumerated, list, bounded and table values map onto the IR's composite values in `pset_value` (one selected item is a scalar, several a list, none null), every scalar through `scalar_value` with the unit its kind states; the declared type is reported only when every scalar shares it, and a table's column types (`with_column_types`, one per column, which the library enforces) always. An `IfcLogical` true or false is a boolean; a single value's unknown (`.U.`) is null with its declared type, as `$` and as an attribute's `.U.`, and an unknown inside a composite value is refused (no null element). A reference value referencing nothing (`PropertyReference` `$`) is null with no declared type; one referencing an entity and an entity-valued predefined attribute are refused, never read in part. A complex property or quantity (`ifc-properties` ≥ 0.5.2, `ExactValue::Complex`) is `PropertyValue::Complex` with no declared type, its members unread; a complex holding itself (`ComplexCycle`) is `Incomplete`, one nested beyond the library's limits `Unavailable`. An enumeration attribute of a predefined set is its constant as text, and an unset optional attribute is null.
- The session's objects are every `IfcObject`, every `IfcContext` (an IFC4 `IfcProject`) and every `IfcTypeObject` (`is_object` in `ifc.rs`). A type object's own `HasPropertySets` resolve through `ifc-properties` ≥ 0.5.1 (`ExactSource::Type`); it has no type of its own, so its type attributes are absent, and door and window leaves call it no door (`openbim-ifc` ≥ 0.8.1). `InvalidQueryObject` (neither occurrence nor type) maps to `Unavailable`, never absence. Resources are never objects.
- `src/resources.rs` owns `is_object` and the resource service: every other instance of a class a rule names (with subclasses when asked), by STEP id, with its GlobalId alias where it is an `IfcRoot` with a usable one. An object class, a class with object subclasses when subtypes are asked, and an undeclared class list none. Never list a class nobody asked for. A resource object's properties are read through `ifc-properties`' material readers (≥ 0.5.3, `exact_material_property`, `exact_material_properties_where`, `exact_material_property_sets_where`; `IfcPropertyService::is_resource` routes every instance that is no session object there), which answer a material definition's own sets (IFC4/IFC4X3 any `IfcMaterialDefinition`, IFC2X3 an `IfcMaterial`), provenance `material:<id>`, a material without sets as proven absence, and every other resource as `InvalidQueryObject`, refused. Never re-derive material sets here. `classifications.rs` classifies resource objects (never objects) through `IfcExternalReferenceRelationship` with an `IfcClassificationReference` (`ifc-classification`) and `IfcMaterialClassificationRelationship` (`ifc-material`); a malformed one refuses every resource object's answer.
- `src/levels.rs` answers `axioval:measured` `level_height` (the only measured name this adapter states; every other one is the engine's and is refused as an invalid request): a storey's placement height in metres to the lowest higher storey of the same `IfcRelAggregates` parent, absent for the highest storey and for any other object. A tilted storey, a sibling at the same or an unreadable elevation, and a storey aggregated twice refuse, never guess.
- `src/relationships.rs` is the exact relationship-selection service. Relationship identities are entity names in the source's own release; end slots come from that release's schema (`ends_of`), never a hand-written table. Every answer carries a `relationship-scan` completeness locator. `RelationshipKind` identities (`axioval:relationship.<kind>`) map onto one relationship type each in `entity_of`, the same in every release; a new kind refuses until mapped. `edges` lists from the same `EdgeIndex` with the same refusals (`refuse_absent_ends`) and evidence (`evidence`) as `select`; keep one reader for both.
- `src/integrity.rs` reports source irregularities through the same `read_instance` reader as selection. Keep them sharing one reader so a warning and a refusal always describe the same instances.
- Absent required ends (`$`) are recorded, not fatal: strict requests refuse, `AbsentEndPolicy::Skip` answers and cites each one, and integrity reports them as warnings. "Required" is per release: `IfcRelSpaceBoundary.RelatedBuildingElement` is optional in IFC2X3 and required in IFC4. Dangling or wrongly shaped ends stay hard refusals and integrity errors. Do not widen skip to cover those.
- `src/identity.rs` reads every `IfcRoot` GlobalId once per session. The same scan decides which objects carry the `ifc-globalid` alias and which integrity warnings are raised, so a missing alias always has exactly one warning. Never attach a GlobalId that is invalid or shared, and keep the `to_uuid`/`from_uuid` round trip until openbimrs/ifc#62 lands.
- `src/attributes.rs` answers the reserved attribute sets from the entity and from its `IfcRelDefinesByType` type object. Attribute slots come from the release schema, never a table. Text, enumeration, boolean, integer and unit-free real values are answered as stated; measures go through `measure.rs`. An entity reference is `PropertyValue::Reference` to that instance (refused when the file does not hold it); an empty aggregate and a logical unknown are exact absences; an aggregate stating members stays refused.
- `src/temporal.rs` reads `IfcDate`, `IfcDateTime` and `IfcTimeStamp` as IR dates and date-times, for property sets and attributes. An `IfcDate` keeps a time zone it states (`xs:date`), never dropped or read as text. An `IfcDateTime` without a UTC offset is `Incomplete`, never read in a guessed zone or downgraded to text; malformed text is `InvalidValue`.
- `src/measure.rs` converts every measure through `ifc_properties::exact_unit` to SI. Never read a measure as a bare number, and never guess a unit when resolution refuses. `resolve` turns an `Incomplete` refusal of a single stated value (number or text) with a declared type into `UnreadableValue` (`IfcPropertyService::unreadable`), keeping the type and locator; composite values, enumeration and attributes keep the refusal.
- `src/layers.rs` reads presentation layers for `axioval:presentation.Layer`: representations, their items, and mapped representations. Answer every distinct layer as a list; never pick one. A model without any layer assignment answers `NotRecorded` with a source-only message, never absence.
- `src/styles.rs` reads surface transparency for `axioval:presentation.Transparency` from body representation items: an item's own style (unique direct `IfcStyledItem`, else its styled layers, mirroring `ifc-style`'s `resolve_item_style`, pinned by a parity test) is authoritative; only items without a surface style fall back to the object's material styles, whose material ids come from `materials.rs`. Read shading and surface-style slots through `ifc-style`, never here. List every distinct value; never average or pick one. A surface style without shading states no transparency and is refused; no style is exact absence, never opaque.
- `src/materials.rs` projects `ifc-material`'s resolved assignment (occurrence first, then type) onto `axioval:material`. Never re-derive which association applies or read material slots here; that is the upstream crate's. Layer thicknesses and constituent fractions go through `measure.rs`; a unit the file does not resolve refuses that measure alone, never the names. `Names` lists every name and category IDS matches a material value against (set, members, member materials); keep it in step with the member properties. A malformed member refuses the whole material, never a partial answer. `ifc-material` (≥ 0.3.0) binds to the file's release: build views through `try_from_view`, never `try_new` (IFC4 slots). An attribute the release does not declare (`MaterialError::NotInSchema`) is absent, since the file cannot state it; every other error refuses.
- `src/bodies.rs` projects `ifc-geometry`'s `body_description` (≥ 0.4.0, openbimrs/ifc#147) onto `axioval:body`: item kinds, swept-solid profiles, placements and extrusions. Never read representation, item or profile slots here; the description is the lowering's own reader. Units come from `exact_unit`, never `ifc_geometry::units::resolve`: an unresolved length unit refuses the body, an unresolved plane-angle unit (carried as NaN) refuses each angle alone. The description is all or nothing, so a body it refuses is refused for every name, never answered in part; an unprefixed item name over several items is a conflict. `Mirrored` is read for every item kind from `BodyItem::is_mirrored()` (≥ 0.4.3, openbimrs/ifc#185: the sign of `item_world`'s determinant, every mapping composed); a degenerate frame refuses it and items that disagree are a conflict, never a guess. Unset optional profile attributes stay absent, never their schema default. Arbitrary profile outlines come from `profile_outline` (≥ 0.4.1, openbimrs/ifc#166) as `OutlineX`/`OutlineY` lists and per void; a curved or unreadable outline refuses only the outline facts, never chords them. Facts are computed once per object and cached.
- `src/classifications.rs` maps `ifc-classification` answers onto `ClassificationService`. Never read classification slots here: release-specific names, notations and hierarchy rules are the upstream crate's. An assignment with no stated system stays `system: None`; never infer one from names or locations.
- `src/frames.rs` answers object frames from `ObjectPlacement`. Placement chains are composed by `ifc-geometry`'s `PlacementResolver` (no features, so no geometry kernel); never re-derive the composition here. The origin goes through the exact project length unit, never `ifc_geometry::units::resolve`, which assumes metres when the file states none. IFC states no front: never report one from the placement's Y axis. `IfcGridPlacement` stays refused.
- `src/doors.rs` answers door leaves (`ObjectFrameService::leaves`) from `openbim-ifc`'s `door_operation` (the facade, `geometry-select` and `properties` only; imported as `openbim_ifc`). Never re-derive leaves, hinge sides or sectors here; map upstream refusals onto `DoorLeavesError` (missing inputs `NotStated`, refused or contradictory ones `Refused`). The lining thickness and panel depths are read here with `exact_predefined_sets` and the exact length unit; the occurrence's own lining set governs, several refuse.
- `src/windows.rs` answers window panels as leaves from `openbim-ifc`'s `window_operation` (≥ 0.7.2, openbimrs/ifc#170; the workspace requires 0.10) when `door_operation` calls the object no door. Never re-derive panels, hinge sides or sectors here; map refusals as for doors (missing inputs `NotStated`, refused or contradictory ones `Refused`, neither door nor window `NotADoor`). Each panel carries its height and tilt; the lining thickness comes from `IfcWindowLiningProperties` through the doors' `lining` helper.
- `src/metadata.rs` states the source metadata the file holds: `application` from every `IfcOwnerHistory.OwningApplication` (`ApplicationFullName`), `project` from every `IfcProject.Name` and `timestamp` from the header's `FILE_NAME.time_stamp`, as written. A field is stated only when every instance reads exactly; an unreadable one leaves the field unread, never drops a value. The schema is the snapshot's and the file name the host's; never state them here.
- `src/coordinates.rs` answers the source coordinate system from the one root `Model` context: `WorldCoordinateSystem` through `ifc-geometry`'s `axis_placement_transform` and the exact project length unit, `TrueNorth`, and an IFC4 `IfcMapConversion` of that context. Several model contexts or conversions are ambiguous and refused. An unstated or unresolvable `MapUnit` stays unknown, never metres; unset `XAxisAbscissa`/`XAxisOrdinate`/`Scale` take the schema defaults. The site placement is the one `IfcSite`'s `ObjectPlacement` through `PlacementResolver` and the exact length unit (`with_site`): no site is `Absent`, several sites or an unresolvable placement `Unknown` with the reason, never a refusal of the whole coordinate system. `ifc-georef` is not used: it depends on `axiolid-core` unconditionally, and this adapter must not take an Axiolid dependency.
- Integrity cardinality warnings (`CONTAINED_TWICE`, `ZONE_MEMBER_NOT_SPATIAL`) come from `ifc-systems` anomalies; do not re-derive them from raw relationships.
- Preserve source-qualified identities and bind every evidence locator to the source fingerprint.
- IFC2X3 TC1, IFC4 ADD2 TC1 and IFC4X3 ADD2 (`ifc-properties` ≥ 0.4.1 resolves all three). A service whose upstream reader does not bind IFC4X3 to its own table refuses IFC4X3 rather than read it as IFC4. `ifc-classification` (≥ 0.2.2) and `ifc-systems` (≥ 0.3.0, every reader, `spatial_placements` included) bind it (openbimrs/ifc#194); `classifications.rs` still compares the release `classification_schema` bound with the session's (`Release::version`) and refuses a mismatch. `ifc-systems` returns `SchemaResolutionError` for a header it binds no release for; the integrity scan is then `IntegrityError::Unavailable`, never free of its warnings. `ifc-schema` (≥ 0.3.0) bundles IFC4X1 and IFC4X2 too, and `SchemaVersion` is non-exhaustive: `Release::from_header` refuses every release it does not name (IFC4X1, IFC4X2, any later one), never aliasing it to a neighbour. Upstream `*Draft` types and read-side records are non-exhaustive; match them with a refusing wildcard arm. Do not add a local resolver for any release.
- Parse/model diagnostics, unsupported schemas, malformed traversal, conflicts, and unsupported values fail closed.
- Keep IFC dependencies behind the facade's optional `ifc` feature; never add Axiolid, geometry-kernel, rule-policy, path, or Git dependencies here.
- This crate adapts **IFC**, not the whole OpenBIM ecosystem. A future CityGML, GAEB, or IDS adapter is a new sibling under `sources/semantic/`, never a module added here.
- `UnavailableOpenBimImporter` remains the explicit conformance placeholder for host-defined importer implementations.
