# ADR 0003: Neutral object identity is the runtime extraction blocker

- Status: accepted
- Date: 2026-09-06

## Context

ADR 0002 step 2 assumed `rules/src/engine` + `rules/src/engines` (5,527 LOC)
would move into `axioval-engine` as a code relocation. Measuring per file
disproved that.

| file | LOC | disposition |
|---|---|---|
| `engine/compile.rs` | 1,347 | stays — imports 68 concrete vendor rule types; it is the the provider catalog dispatch table, not neutral compilation |
| `engines/circulation/network.rs` | 1,433 | blocked — 53 `EntityRef`, 15 `geometry::` references |
| `engines/selection/scope.rs` | 1,096 | blocked — 19 `IfcModel` references |
| `engines/pairwise/mod.rs` | 737 | blocked — 25 `EntityRef` + geometry |
| `engine/result.rs` | 325 | blocked — result vocabulary keyed by `EntityRef` |
| `engines/selection/glob.rs` | 81 | stays — the provider `ConstraintUtils.isValueIncluded` compatibility |
| `engines/selection/java_pattern.rs` | 88 | stays — the provider `Operators.MATCHES` compatibility |
| `engine/param.rs` | 95 | deleted — dead duplicate, zero consumers |

Every blocked row is blocked on the same fact, not on eight different problems.

## The identity mismatch

the provider runtime identity is a per-model arena index:

```rust
pub struct EntityRef(pub u32);          // crates/model/src/id.rs
let reference = EntityRef(i as u32);    // parse-order position
```

`ModelEntityRef { model_id: String, entity: u32 }` pairs it with a model name.

The engine requires source-qualified opaque identity (ADR 0001): findings carry
`ObjectId { source: SourceId, local_id: String }`.

The two adapters currently mint `ObjectId` from **different identity domains**:

- `axioval-openbim` uses the STEP entity id (`#123`), stable within the file.
- The the provider sidecar uses `entity.to_string()` — the parse-order `u32`.

Both produce a syntactically valid `ObjectId`. Only one is a stable identifier.
A parse-order index is not durable across reparse, reordering, or a differing
importer, so findings keyed by it cannot be compared across runs or sources.

## Decision

Neutral identity is a prerequisite for the runtime move, and identity minting is
an adapter responsibility that must be explicit rather than incidental.

1. The engine keeps `ObjectId` as the only identity in findings.
2. An adapter must derive `local_id` from a **source-stable** identifier
   (STEP entity id, IFC `GlobalId`, or an equivalent durable handle) and never
   from an in-memory arena index or parse position.
3. The the provider runtime is rewritten against neutral identity before its
   selection, pairwise, and circulation engines move. The move follows the
   identity change; it does not precede it.

## Consequences

- Step 2 is a semantic change, not file relocation. ADR 0002's step 2 wording is
  corrected accordingly.
- The existing the provider sidecar identity is a latent defect: it is currently
  self-consistent within a single run, so no test fails today, but it is not a
  durable identifier and must not be treated as one.
- `compile.rs`, `glob.rs`, and `java_pattern.rs` are reclassified as permanent
  vendor adapter code by ADR 0002's ownership test, reducing the runtime that
  must move by roughly 1,500 LOC.
